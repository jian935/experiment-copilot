# 方法论：每一个口径，都是被否决过的备选

> 版本：2026-11-01（M13-H1）
> 复现：`npm run method` —— 第 1–4 节的每一个数字都来自它（固定种子，逐位可复现）；
> 引用 `docs/EVAL.md` 的地方在正文里直接标了出来（那几条来自另外的脚本）。
> 实现与单测见文末「怎么复核」。

这篇文章只回答一类问题：**为什么是这个口径，而不是教科书上那个更常见的**。

统计实现最容易骗自己的地方不是写错公式，而是「公式没错、但用错了场合」。
所以下面每一项都按同一个结构写：备选是什么 → 它在什么条件下坏 → 坏的代价有多大 →
我们选了什么 → 我们的选择在什么条件下也会坏（这一条不许省）。

---

## 0. 先把「数字从哪来」说清楚

| | 做法 | 为什么 |
|---|---|---|
| 小样本格点（n ≤ 1000） | **精确枚举**：n=30 时只有 31×31=961 个可能结果，按二项概率加权求和 | 能算准就不该抽样。抽样版与枚举差 0.5pp 以内，但那 0.5pp 会变成结论里的假精度 |
| 大样本格点（n = 20000） | 蒙特卡洛 4000 次，固定种子 | 枚举是 4 亿个格子，跑不动；而抽样在已验证的小样本格点上与枚举一致，可以外推 |
| 数据集上的复核 | 120 个实验（种子 `20261031`），跑真引擎 `analyze()` | 模拟能说明「方法对不对」，只有真数据能说明「在这个产品里会动到谁」 |

一处必须记住的口径：**「覆盖率」是区间的性质，「检出率」是检验的性质**，两者不能互相顶替。
下面第 1 节谈覆盖率，第 4 节谈检出率。

---

## 1. 差值区间：为什么是 Newcombe，不是 Wald

### 1.1 备选长什么样

Wald（教科书默认，绝大多数 A/B 工具的实现）：

```
Δ̂ = p₂ − p₁
SE = √( p₁(1−p₁)/n₁ + p₂(1−p₂)/n₂ )
CI = Δ̂ ± 1.96·SE
```

Newcombe method 10（本项目 `stats.ts::newcombeDiffCI`）：先用 **Wilson 得分区间**分别算两臂，
再把两个区间的「尾部不对称」按平方和搬到达差值上：

```
[l₁,u₁] = Wilson(p₁,n₁)     [l₂,u₂] = Wilson(p₂,n₂)
CI = Δ̂ − √( (p₁−l₁)² + (u₂−p₂)² )  ,  Δ̂ + √( (u₁−p₁)² + (p₂−l₂)² )
```

### 1.2 Wald 坏在哪：它不说谎的地方只有大样本中间段

精确枚举的覆盖率（标称 95%，null 下 p₁=p₂）：

| 基线 | n/臂 | Wald 覆盖率 | Newcombe | 宽度 Wald / Newcombe |
|---|---|---|---|---|
| 0.12% | 30 | 100.0% | 100.0% | **0.906pp / 22.869pp** |
| 0.12% | 100 | 100.0% | 100.0% | **0.874pp / 7.599pp** |
| 0.12% | 20000 | 94.9% | 96.2% | 0.135pp / 0.140pp |
| 1.2% | 30 | 99.9% | 100.0% | 7.617pp / 24.314pp |
| 1.2% | 100 | 98.0% | 100.0% | 5.536pp / 9.237pp |
| 1.2% | 20000 | 94.7% | 94.8% | 0.426pp / 0.428pp |
| 5% | 30 | 97.2% | 99.8% | 20.555pp / 28.760pp |
| 5% | 100 | 94.6% | 98.5% | 11.886pp / 13.470pp |
| 5% | 20000 | 94.8% | 94.8% | 0.854pp / 0.855pp |
| 20% | 30 | 94.0% | 93.4% | 39.599pp / 39.912pp |
| 20% | 100 | 94.8% | 94.5% | 22.032pp / 22.085pp |
| 20% | 20000 | 94.8% | 94.8% | 1.568pp / 1.568pp |
| 50% | 30 | 94.8% | **90.8%** | 49.749pp / 46.981pp |
| 50% | 100 | 94.4% | 94.4% | 27.579pp / 27.072pp |
| 50% | 20000 | 94.8% | 94.8% | 1.960pp / 1.960pp |

三件事同时成立，而且都很反直觉：

**① 覆盖率不是判据，宽度才是。** 0.12% 基线、30 个样本时两者覆盖率都是 100%，
但 Wald 给出的平均宽度是 **0.906pp**，Newcombe 是 **22.869pp**。Wald 之所以「覆盖住了」，
是因为最常见的那批样本（两臂都 0 次）让它把区间塌成了一个点 `[0, 0]`，正好压在真值上；
剩下那些格子又窄到 ±0.45pp。它把一个「什么都不知道」的样本，说成了「精度很好」。
**覆盖率 100% 的区间可以是毫无信息的区间。**

**② 零事件是 Wald 的结构性崩塌，不是边界情况。** 两臂都是 0 次时：

```
Wald      = [0, 0]                    宽度 0，等于宣称「效应精确等于 0」
Newcombe  = [−0.0192pp, +0.0192pp]    宽度落在「样本能分辨的最小量级」上
```

别以为这只发生在玩具数据上：投诉率基线 0.12%，每臂 1000 个样本时期望事件只有 1.2 个，
**观测到 0 次的概率是 e^−1.2 ≈ 30%**。而分层子群（新/老用户 × iOS/Android 再切天）
与「只看前两天」的早期数据，正好就是这个量级。Wald 在这些格子上给出宽度为 0 的区间，
下游任何拿宽度当权重的东西（精度加权、区间是否跨 0、森林图的线长）都会失真。

**③ 结论真的会翻，不只是数字变好看。** 枚举里搜出「Wald 判有提升、Newcombe 判证据不足」的格子：

| 观察 | Wald | Newcombe |
|---|---|---|
| n=50/臂，对照 0 次、处理 4 次 | [0.48, 15.52]pp → **有提升** | [−2.84, 16.62]pp → 证据不足 |
| n=50/臂，对照 0 次、处理 5 次 | [1.68, 18.32]pp → **有提升** | [−1.36, 19.10]pp → 证据不足 |
| n=50/臂，对照 1 次、处理 6 次 | [0.19, 19.81]pp → **有提升** | [−1.92, 20.63]pp → 证据不足 |

这类格子的共同点是「对照臂几乎没发生事件」。Wald 把 p₁=0 处的方差当成 0，
于是整条区间的宽度只由处理臂决定——这是它系统性偏窄的根源，不是连续性校正能修的（校正只挪 0.5/n）。

### 1.3 代价：Newcombe 在最常用的区间里也要付一点宽度

真实口径（1.19% vs 1.24%，每臂 2 万）：Wald 覆盖 95.2%、宽度 **0.429pp**；
Newcombe 覆盖 95.3%、宽度 **0.431pp**。差距 0.002pp，**在这个样本量下几乎是免费的**。

这就是选择它的真正理由：**用不到 0.5% 的宽度，换掉「极端比例 + 小样本」下的整类错误**。

### 1.4 我们的选择也会坏，坏在哪写在这里

`p ≈ 0.5、n = 30` 时 Newcombe 覆盖率 **90.8%**，比 Wald 的 94.8% **更差**。
这是 method 10 在「比例接近 0.5 且样本很小」时的实际表现（本文用枚举测出来的，不做理论归因）。

为什么仍然接受：

1. 本项目的所有指标都在 **0.12%–20%** 这个区间（退款率 1.2%、投诉率 0.12%、转化率 4.5%–6%、
   ARPU 的购买率约 8%），50% 的比例在这个产品里不存在；
2. 每臂样本量在数千到数万，最小可信的子群也在数千量级——真要出现 n=30 的格子，
   UI 会明确标「样本不足」，而不是让你相信一个 90.8% 覆盖率的区间。

**这一条不隐藏、也不打算「优化」掉。** 换成一个在 p=0.5 更好的区间（比如 Miettinen-Nurminen 的
迭代解），会在我们真正使用的那一头引入新风险，而收益是零——那是为了漂亮的表格做工程。

## 2. 多重比较：清单用 Holm，分层用 BH q=0.1

### 2.1 先算清「看太多」这件事有多大

120 个实验、每个都用 α=0.05，**即使全部无效**，至少出现一个「显著」的概率是

```
1 − 0.95¹²⁰ = 99.79%
```

所以「总有一个能上线」不是运气，是算术。这一条在页面上是直接写出来的（列表页勾「全局校正」）。

### 2.2 两种错误，不能混着说

| | 控什么 | 代价 | 本项目用在哪 |
|---|---|---|---|
| **Holm**（FWER） | 「至少错一个」的概率 ≤ α | 在 m=120 时极保守 | **跨实验清单**：要下结论 |
| **BH**（FDR） | 「拒掉的里面假阳性的比例」 ≤ q | 允许少量假阳性 | **单实验内的分层扫描**：要找线索 |

模拟（200 次 × 120 个检验，其中 24 个真有效 → π₀ = 96/120 = **0.8**，
真效应的 p 来自功效约 0.8 的替代分布）：

| 口径 | 实测 FDR | 功效 |
|---|---|---|
| 不校正 α=0.05 | **19.8%** | 79.0% |
| Bonferroni α=0.05 | — | 23.2% |
| Holm α=0.05 | — | 23.5% |
| BH q=0.05 | 4.2%（上界 q·π₀ = 4.0%） | 50.0% |
| **BH q=0.1** | **8.0%（上界 q·π₀ = 8.0%）** | **62.7%** |
| BH q=0.2 | 15.7%（上界 q·π₀ = 16.0%） | 75.1% |

三个观察，第二个是最容易被说错的那个：

- **不校正的功效最高（79.0%），但拒掉的东西里 19.8% 是假的**——每 5 个「显著」里有 1 个是噪声。
  清单页要做的正是「下结论」，这个比例不可接受。
- **BH 的实测 FDR 低于标称 q，不是因为检验负相关，而是因为 π₀ < 1。**
  BH 控的是 `FDR ≤ q·π₀`，这里 π₀ = 0.8，所以 q=0.1 的真实上界是 **8.0%**，实测 8.0%；
  q=0.05 的上界 4.0%、实测 4.2%（200 次模拟的抽样误差）；q=0.2 上界 16.0%、实测 15.7%。
  三条都对得上——**这说明实现是对的，而不是「比承诺更好」**。
  （把「低于标称值」当成「BH 很保守，可以再放宽」是最常见的一步错棋；放宽到 q=0.2 时
  FDR 已经 15.7%，跟不校正的 19.8% 只差 4 个点。）
- **Holm 在 m=120 时功效只有 23.5%**。但这恰恰是它在清单页该有的样子：
  120 个实验一起看，本来就不该有几十个「可以上线」。实测见 `docs/EVAL.md` §4i：
  原始 68 个显著 → Holm 后 **53** 个（收回 15 个，其中 5 个注入效应为 0）。

### 2.3 为什么分层扫描是 q=0.1 而不是 0.05

因为在**实际使用的 m 下，q=0.1 恰好等于「不校正的 α=0.05」**：

分层扫描每一维只有 **m=2** 个格子（新/老用户；iOS/Android）。BH 在 m=2、q=0.1 时的门槛是：

```
最小的 p  ≤ 1/2 × 0.1 = 0.05     ← 与不校正的 α 完全相同
次小的 p  ≤ 2/2 × 0.1 = 0.10
```

也就是说：**我们不靠降低单个分层的严格度来换检出，而是白拿了一层 FDR 保护。**
如果这里写 q=0.05，最小 p 的门槛会变成 0.025——那是在样本量本就不足的分层上，
主动放弃一半的检出率，换一个我们并不需要的 FWER 保证。

### 2.4 诚实的部分：q 目前根本不是瓶颈

在 120 个实验上把 q 从 0.05 扫到 0.2，检测结果**完全不变**：

| q | 判异质 | 其中真异质 | 误报 | 漏报 |
|---|---|---|---|---|
| 0.05 | 13 | 12/15 | 1 | 3 |
| **0.1** | **13** | **12/15** | **1** | **3** |
| 0.2 | 13 | 12/15 | 1 | 3 |

原因是检测器是**合取口径**：交互显著（`interactionAlpha=0.01`）**且** 一个分层显著为正
**且** 另一个分层无效。这三条里前两条比 q 严得多，q 还没轮到就定完了。

所以准确的说法是：**q=0.1 是一个有原则的默认值，不是这个检测器的调参结果。**
要提升异质检出（现在漏 3/15），该动的是合取口径本身，不是 q——
把 q 放宽到 0.2 只会让人以为调了参，实际一个都没多检出。这句话写在文档里，
是因为它是最容易被「顺手优化」掉的地方。

## 3. 护栏：为什么只有退款率会真的拦住上线

### 3.1 三种口径，都是正式检验，只是严度不同

护栏用**非劣检验**（单侧），margin 是「业务能容忍的最大恶化」，不是统计默认值：

| mode | 拦截条件 | 语义 |
|---|---|---|
| `harm_and_practical` | 统计上确有恶化 **且** 恶化≥margin | 「坏得确定，而且坏得够多」 |
| `confirm_beyond_margin` | 有把握恶化**超过** margin（需跨过 margin + z·SE） | 最严：宁可漏，不可冤 |
| `non_inferiority` | 拿不出「恶化在容忍度内」的证据就拦 | 最保守：举证责任在改动方 |

### 3.2 mode 的选择：模拟 + 数据集，两个证据

模拟（退款率基线 1.19%，每臂 2 万，margin 0.4pp，单侧 α=0.005，2000 次）：

| 真实恶化 | `harm_and_practical` | `confirm_beyond_margin` | `non_inferiority` |
|---|---|---|---|
| +0.0pp | 0.1% | 0.0% | **13.1%** |
| +0.2pp | 3.4% | 0.0% | 77.6% |
| +0.4pp（= margin） | 48.1% | 0.5% | 99.4% |
| +0.8pp | **99.9%** | **72.3%** | 100.0% |

数据集上（120 个实验，只改 `refundRate.mode`）：

| mode | 拦截数 | 其中真护栏族 | 其它族误拦 |
|---|---|---|---|
| **`harm_and_practical`** | **15** | **15/15** | **0** |
| `confirm_beyond_margin` | 14 | 14/15 | 0 |
| `non_inferiority` | 30 | 15/15 | **15** |

结论很清楚：`non_inferiority` 把误拦从 0 抬到 15（每个都是「主指标大涨但退款率没证据说没变坏」），
`confirm_beyond_margin` 会漏掉 1/15 的真实伤害（模拟里在 +0.8pp 时漏掉 27.7%）。
`harm_and_practical` 是唯一在两个证据上都干净的。

一句容易说错的话，这里写清楚：**这不是「三选一挑最好看的」。**
`harm_and_practical` 在两个方向的错误上都可接受，是因为退款率的 SE（null 下 0.108pp、
恶化 0.8pp 时 0.125pp）与 margin（0.4pp）差着一个量级。如果 SE 涨到 0.2pp（≈ 样本减到 1/3.4），
这个口径会同时变差，那时该做的是**延长时间/加样本**，不是换一个更好看的口径。

### 3.3 为什么投诉率不拦、延迟也不拦

| 指标 | 基线 | SE/臂 | margin | 为什么不 gating |
|---|---|---|---|---|
| 退款率 | 1.19% | 0.108pp | 0.4pp | 有业务含义的容忍度明确，且 SE 远小于它 |
| 投诉率 | 0.12% | ~0.035pp（基线的 **29%**） | 0 | 任何有意义的容忍度（比如相对 +10% = 0.012pp）都**小于 SE**，margin 只能取 0；此时"确认上升"要观测到 +0.09pp，噪声一大就抖 |
| P95 延迟 | 各接口差异大 | 与基线同量级 | 相对 +5% | 相对门槛能跨接口复用，但噪声大且与体验损失非线性 → 只展示 |

**「只硬判退款率」不是偷懒，是三条不同的理由指向同一个结论**：只有退款率同时满足
「基线够高（SE 远小于容忍度）+ 容忍度有业务定义 + 损失近似线性可加」。
另外两个进了报告但不进决策——**报告与决策分开，是这一层唯一的设计原则。**

### 3.4 护栏是另一套货币

护栏恶化不能拿主指标收益来抵。这不是道德判断，是量纲：
主指标是 pp（或元），护栏是退款率/投诉率/延迟——它们的兑换率需要业务定价，
而定价方案一旦进代码，就会变成「用 0.3pp 转化率买 1pp 退款率」这种没人签字的东西。

所以 `src/lib/loss.ts` 的期望损失有这个结构：

```
硬门禁（SRM / 护栏 / 已确认负向）→ 直接否决，不看净价值多大
建议（异质）                    → 只给「限定人群上线」，不否决
净价值                          → 只在门禁之内做权衡
```

实测（`docs/EVAL.md` §4j）：裸规则会为 **15 个**「护栏已恶化但主指标大涨」的实验建议上线，
它们的实测退款率是 **1.19% → 2.03%（1.71×）**。

## 4. P(B>A)：为什么用正态近似，而不用精确后验

### 4.1 备选与实现

率口径是 Beta-Binomial 后验：treatment ~ Beta(c₂+1, n₂−c₂+1)，control ~ Beta(c₁+1, n₁−c₁+1)。
`P(B>A)` 的精确值是两独立 Beta 之差的概率，需要数值积分（或不完全 Beta 的连分式）。
实现取的是正态近似：

```
P(B>A) ≈ Φ( (m_t − m_c) / √(v_t + v_c) )
```

### 4.2 近似误差有多大（对照精确值）

精确值用「不完全 Beta 连分式 + 在标准化坐标上做 Simpson（8000 段）」算，
避免均匀网格取不到尖峰（基线 1.2%、n=2 万时峰宽约 5e-4）：

| 场景 | 精确值 | 正态近似 | 误差 |
|---|---|---|---|
| n=20/臂，基线 5% | 69.70% | 68.69% | **1.01pp** |
| n=100/臂，基线 5% | 79.65% | 79.10% | **0.55pp** |
| n=1000/臂，基线 5% | 83.56% | 83.48% | 0.08pp |
| n=20000/臂，基线 1.2% | 99.53% | 99.53% | 0.01pp |
| n=20000/臂，基线 1.2%（无效应） | 50.00% | 50.00% | 0.00pp |
| n=500/臂，基线 30% | 95.41% | 95.43% | 0.01pp |

**每臂 ≥ 1000 时最大误差 0.08pp；每臂 ≤ 100 时最大误差 1.01pp。**

### 4.3 为什么不用精确解

| 理由 | 说明 |
|---|---|
| **可复现** | 精确解要迭代（收敛容差）或积分（网格密度），两种实现给的最后一位可能不同；正态近似是闭式，同一输入永远同一输出 |
| **同源** | `P(B>A)`、可信区间、期望损失三者用同一个 `Δ ~ N(meanDiff, varDiff)`。如果用精确后验算概率、用正态算区间，就会出现「P(B>A)=97% 但 95% 区间跨 0」这种自相矛盾的卡片 |
| **误差在显示精度之内** | 页面把概率显示到一位小数（0.1pp），每臂 ≥ 1000 时近似误差 0.08pp **小于这一格**，最后一位最多偏 1；而 n=20 时的 1.01pp 是显示精度的 10 倍 |

### 4.4 使用边界（写进 UI 的）

- 每臂 < 100 时，`P(B>A)` 的小数位**不可引用**（误差 1.01pp 是显示精度 0.1pp 的 10 倍，连第一位都不可信）。
  这类实验在页面上会同时给出「样本不足」的提示，概率值只作方向参考。
- 连续指标（ARPU）走 `bayesNormal`，公式与 Beta 版**逐字对应**，所以两个口径的概率可以直接横比——
  换指标不会换掉「更优概率」的定义。

## 5. 所有被否决的备选，一张表

| 位置 | 否决的备选 | 否决理由（一句话） | 代价 |
|---|---|---|---|
| 差值区间 | Wald / 加连续性校正的 Wald | 零事件时宽度为 0，极端比例下宽度系统性偏窄 | 大样本下多 0.002pp 宽度 |
| 差值区间 | Miettinen-Nurminen 迭代解 | 在 p≈0.5 更好，但我们的指标不在那里；引入迭代收敛风险 | 未采纳 |
| 跨实验 | 不校正 | 120 个实验下「至少一个显著」= 99.79% | — |
| 跨实验 | BH | 允许假阳性（q=0.1 时实测 FDR 8.0%），而清单是用来**下结论**的 | 见 §2.2 的对照表 |
| 分层扫描 | q=0.05 | m=2 时最小 p 的门槛从 0.05 降到 0.025——在样本本就不足的分层上主动提高要求 | 未采纳 |
| 护栏 | `non_inferiority`（举证责任倒置） | 数据集上误拦 15 个（主指标大涨、护栏无证据变坏） | 未采纳 |
| 护栏 | `confirm_beyond_margin` | 模拟中 +0.8pp 真实伤害漏掉 27.7% | 未采纳 |
| 护栏 | 给护栏定价、并入净价值 | 兑换率需要业务签字，写进代码就是替业务做决定 | 硬门禁 + 建议 两层结构 |
| P(B>A) | 精确 Beta 积分 / MCMC | 不可复现、且与区间不同源（会自相矛盾） | 每臂 <100 时误差 1pp |
| 稳健标准误 | i.i.d. 二项式 SE | 实测把率口径的 A/A 误报率推到 **9.70%**（名义 5%；真实数据普遍过离散） | 默认 `robust` |
| 区间 | Bootstrap 百分位法（用于率指标） | 率指标有闭式精确解，重抽样只是把误差引进来 | 只用于比值/连续/分位数 |
| 序贯 | 用序贯阈值改 `decision` | 改口径会让 120 条真值标定全部作废 | 序贯只作为并行口径报告 |
