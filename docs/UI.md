# UI 设计说明（M2）

> 目标：打开任一实验，**3 秒内**看懂「能不能上、为什么、有多少把握」，并且每个数字都能点开核对。

## 一、七个入口 + 一套主题（列表 / 详情 / 证据链 / 对比 / ⌘K / 设计 / 决策）

### 1. 实验列表（`#/`）

| 区块 | 内容 | 设计意图 |
|---|---|---|
| 顶部 | 实验总数、数据版本（seed）、「合成数据」标签 | 先声明数据性质，不假装是真实业务数据 |
| 顶栏「数据源」芯片 | `内置 · 120 例` / `导入 · N 例`，点开可切换、可删本机存档 | 导入过的数据必须一眼看出「我现在看的是哪一份」——内置带已知真值、导入的真实数据没有，这决定评测看板能不能用。说错这一句，后面所有数字都会被误读 |
| 5 个统计块 | 全部 / 建议上线 / 不建议上线 / 定向上线 / 无法下结论 | 可点击＝筛选器；让「拦截率」这个产品价值可视 |
| 筛选行 | 搜索（名/ID/假设/指标）、类型下拉、排序（编号 / 效应大小 / p 值） | 分析师的真实动作是「先看最可疑的那几个」 |
| 表格 | 实验、结论徽章 + 规则名、主指标、control→treatment、差值 + 迷你 CI、p、样本 | 一行里同时给出「结论」和「证据形状」 |

迷你 CI 是列表的关键：**线是否跨过虚线 0** 一眼可判，不用读 p 值。

### 2. 实验详情（`#/e/<id>`）

从上到下是固定的「先结论、后证据」顺序：

1. **结论卡**：大字决策（建议上线 / 不建议上线 / 定向上线 / 无法下结论）+ 规则编号（SRM / GUARDRAIL / NEGATIVE / HETEROGENEOUS / NOT_SIG / POSITIVE）+ 一句人话理由 + 三个关键数（差值、p、样本）。
2. **三条硬前置检查**：SRM 分流、主指标显著性、护栏。**先看这三条，再看别的**——这是产品的方法论，不是装饰。
3. **森林图**：整体 + 4 个分层，点＝差值、横线＝95% CI、竖虚线＝0。用来回答「是整体有效还是只有某类人有效」。
   单位跟着主指标走：转化率口径的刻度是 pp，ARPU 口径是元——两者混排会把「0.42 元」显示成「+0.42pp」。
4. **分日趋势**：7 天两条线，用来发现「某天开始突然拉开」这类数据问题。
5. **指标明细**：control / treatment 的样本、转化、转化率、差值、CI、相对提升、p。
6. **三个 Tab**：**维度切片** / 护栏指标（谁参与决策、是否恶化）/ **计算过程**（把公式和代入的数字摊开）。
   「维度切片」顶部是一排 chip（设备 / 新老用户 / 周内周末 / 数据里带来的渠道、城市…），
   选了哪个维度，下面的表**和森林图**就一起换成那个维度——两边不一致会让读者以为是两个结论。
   每组给 p 与 **BH 校正后的 q**，底部给 **Cochran Q**（效应是否随该维度变化）与「最强 vs 最弱」，
   区间重叠时直接写「还不足以说它们真的不同」。
7. **ARPU 因子分解**（仅连续口径实验）：把 `ΔARPU` 拆成「转化率贡献 / 客单价贡献 / 交叉项」三根条，
   并标出两者方向相反的情况（打折拉量：转化率涨、客单价跌，ARPU 看着没动）。
8. **序贯监控（窥探校正）**：|z| 轨迹 + OBF α 消耗边界 + naive 1.96 三条线画在一起。
   读者真正想知道的是「这次显著是真显著，还是看出来的」——所以两条线的相对位置就是答案。
   四个格子给：最终名义门槛（p<3.60%）、always-valid p、当前 z 与边界、三套口径曾达到显著的对照。
9. **新颖效应（时间维度）**：逐日效应柱图（每根柱子是**独立**估计，不是累计）+ 两段的日级均值虚线 + 切点竖线。
   四个格子给：前半段 / 后半段 / δ + p / **可检出下限**。判「未见衰减」时下面紧跟一句
   「小于 ±X 的衰减这个样本量看不出来」——不写这句，读者会以为已经排除了衰减。
10. **期望损失决策（该不该上）**：把差值的后验当 Normal(Δ̂, SE²)，算「上线」相对「不上线」的净价值。
   四个格子给：E[收益] / E[损失]×k / 净价值（已扣 MMP）/ 等价点。
   下面的曲线横轴是「真实效应」、纵轴是净价值——k>1 时它在 0 附近**左右不对称**，
   等价点因此被推到 0 右边；把点估计和等价点一起标出来，
   「点估计明明是正的却还不建议上线」就变成一眼能看的事。k 与 MMP 是两个滑杆，可现场调。
   门禁（SRM / 护栏拦 / 已确认负向）否决时整块变红；异质只给琥珀色建议、不否决。
11. **还要跑几天**：中位天数 / 80% 分位 / 「跑满也等不到」概率 + 把握度曲线；4 条简化假设就摆在面板里。
12. **多臂对比**（仅 k>2 出现，两臂实验这一块完全不渲染）：每臂一行，给样本 / 主指标 / 差值 +
   **Dunnett 同时区间** / 相对提升 / 边际 p / **校正 p** / **P(best)** / 该臂自己的护栏。
   下面三格回答三个不同的问题：全局检验（这个实验到底测出东西没有）、最可能最优的臂、
   赢家诅咒的量级与「Dunnett 比 Bonferroni 少付多少」。焦点臂那行用底色与「决策依据」徽章标出来，
   但**森林图里不会只画它**——森林图把每个臂都画上，否则表里有数字、图上没有，读者会以为漏了。
   底部一句话写清 SRM 用的分流比例来自哪里（声明 / trafficSplit / 等分），因为用错期望做 SRM
   会把正常实验判成异常。
13. **稳健性（去极值）**（仅 ARPU 口径；转换率实验这块完全不渲染）：ARPU 是比值指标，
    「+8% 可能来自三个代购账号」。面板给三件互相独立的事——
    ① **五档截尾扫描**（原始 / 0.5% / 1% / 2% / 5%）画成敏感性曲线（折线＝差值，阴影带＝95% 区间）；
    ② **收入集中度**（最重的前 1%/5%/10% 曝光贡献多少收入，附「人人等额时是 1%」的基准 + Gini）；
    ③ **单点杠杆**（精确删掉某一行重算，给 `p 0.051 → 0.026` 这种读数）。
    顶部一枚判定徽章（结论稳定 / 对极值敏感 / 符号会翻转 / 不可用），下面一句人话说清翻转发生在哪一档。
    两处刻意的措辞：档位表里那一列叫 **`p*` 而不是 p**（面板底部写明「截尾分位是看着数据定的，
    p 不再服从名义 α」并附模拟依据：截尾口径覆盖 33.67% vs 原始 94.67%）；
    底部写清「**截尾单位 = 你的数据粒度**」——聚合数据只能去掉整格异常，要用户级截尾需要用户级明细表。
    这两句话不是免责声明，是这张表的读数前提。
14. **真值对照**（默认折叠）：合成数据才有，展示注入效应、真实决策、引擎判定是否一致。

> 主指标换成 ARPU 时，上面 1–6 的文案、单位、检验方法都跟着换（`analysis.primary` 是唯一入口），
> 护栏那一栏**不换**——退款率永远是率口径。若实验声明了 ARPU 但数据里没有 `revenue`，
> 页面顶部会出现一条黄色提示说明「已退回转化率口径」，不会让人误以为看的是 ARPU 的结论。

> 导入的数据存在**本机浏览器**（IndexedDB；不可用时降级到 localStorage，再不行只能用内存并明确警告「刷新即丢」），
> 不上传任何服务器。顶栏下拉的页脚显示的是**真实**的存储后端，不是写死的「IndexedDB」。

### 3. 证据链抽屉（右侧滑出）

- 时间线形式，顺序固定：SRM → 主指标 →（副指标 / CUPED）→ 序贯 → 新颖效应 → 分层×2 → 交互 → 护栏×3 → 结论。
  率口径实验是 13 条；ARPU 实验换成「ARPU + 因子分解 + 稳健性」三条，共 14 条（没有「副指标」那条，它本身就是主口径）。
- 每条带类型徽章（SRM / 主指标 / 稳健性 / 分层 / 护栏 / 结论）、完整数值描述、`E1..E14` 编号（按实验口径略有增减）。
- **M3：每条都能展开看「逐步代入」**——`① 两变体转化率 → ② 合并比例与 SE → ③ z 与 p → ④ Newcombe 区间 → ⑤ 判定阈值`，公式和实际数字并排，能手算复核。
- **M3：结论那条展开是「规则轨迹」**——6 条规则按固定优先级排列，标出命中 / 被更高优先级覆盖 / 未触发，并写明各自的条件与实算明细。
- 每条右侧有「复制链接」，得到 `#/e/E001?ev=E6` 这种证据级深链。
- 底部「一键复算」：用同一份数据重跑引擎，逐项比对，返回「✓ 复算一致（13 条证据，0.2ms）」。
- 附带「数据与口径」小表：检验方法、区间方法、多重比较、α、SRM 阈值、样本合计。

### 4. 实验对比（`#/compare?a=<id>&b=<id>`）

入口有两个：详情页右上角「与其它实验对比」，或**列表页左侧勾两个** → 底部浮出选择条 → 「对比这两个」。
勾选框不是装饰，它解决的是同一个改动的两次实验结论相反时「到底哪一次可信」这个问题。

| 区块 | 内容 | 设计意图 |
|---|---|---|
| 两张结论卡 | 各自的决策徽章 + 差值 + p + 样本 + 指标/类型/日期 | 先看结论，再看差异从哪来 |
| 可比性提示 | `block`（红）：单位不同不能同轴；`warn`（琥珀）：指标 / 观察期 / 分流比例不同 | **先说不能比的地方**，而不是藏在脚注里 |
| 森林图 | 同单位 → **共用一条横轴**；不同单位 → 竖排两张、各自一条轴 | 线长差本身就是「谁更不确定」；各画各的轴会把两个区间拉伸成差不多长 |
| 逐项对照 | 15 行：结论 / 规则 / 差值 / CI / p / 相对提升 / 样本 / 检验口径 / CUPED / 护栏拦截 / 分层异质 / 序贯 / 新颖效应 / SRM | 同一行同一口径；缺数据写「—」而不是空着（空着会被当成 0） |

两条硬规矩：

1. **单位不同一定拒绝同轴**。pp 与元不可通约，叠在一条轴上比长短没有意义。这条判定在 `src/lib/compare.ts`（纯函数），
   单测跑了 120 个实验的 **7140 个两两组合**，断言「判成同轴」与「单位一致」严格等价——不是抽查几个。
2. **不拿注入场景（`archetype`）当不可比的理由**。那是数据生成时注入的真值标签（正向 / 负向 / 异质 / 护栏恶化…），
   不是实验设计类别；拿它说「两类实验效应量级不同」是范畴错误，真实导入的数据里这个字段根本无从得知。
   第一版写进去了，看着像"严谨"，实际是编了个规则。

这一屏**只做对照，不产生新结论**：两边的决策仍由各自引擎判定，对比视图不改任何一条。

### 5. 全局搜索面板（⌘K / Ctrl+K）

顶栏「搜索 ⌘K」或键盘直接唤出。它能搜到的不只是实验列表那些字段：

| 可搜 | 例子 | 为什么要有 |
|---|---|---|
| 实验编号 / 名称 / 假设正文 | `E029`、`支付方式排序` | 表格里本来就能搜 |
| **规则名与结论** | 输 `护栏` 出来被 GUARDRAIL 拦住的那批 | 用户常想起的是「那个被拦的」，不是编号 |
| 主指标 | `ARPU` | 直接筛出连续口径的实验 |
| **功能动作** | `看板`、`导入`、`对比` | 表格里找不到「切数据源」这种事 |

三条取舍：

1. **多词是 AND**：`支付 结算` 必须两条都出现才算命中，所以要的人越搜越少。
2. **排序有定义**：完全相同 > 前缀 > 包含 + 字段权重（编号 6 / 主指标 3 / 正文 1），
   所以搜 `E001` 一定第一个就是 E001。整套检索在 `src/lib/search.ts`（纯函数，15 条单测）。
3. **不用正则**：用户想查 `p<0.05` 是正常的，而正则要么抛错要么静默错配——一律 `indexOf`。
   （写冒烟脚本时真的被这条咬过：`Runtime.evaluate` 传进去的表达式里 `
` 被模板字面量变成真换行，
   而**正则字面量里含换行在 JS 里是语法错误**——页面求值直接失败、`result` 为空。）

键盘走完全程：↑↓ 选、**↵ 直达**、Esc 关，选中的行永远滚进视野。
对比视图的选择器复用同一个 `searchExperiments`，两处匹配口径不可能漂移。

### 主题（浅 / 深 / 跟随系统，顶栏一键循环）

**所有颜色都走 CSS 变量**：Tailwind 里写作 `rgb(var(--c-base) / <alpha-value>)`，
SVG 色板（原 `palette.ts` 的十六进制）也换成 `rgb(var(--c-ship))`。于是切主题只是给 `<html>` 换一个类：

| 好处 | 说明 |
|---|---|
| 一个 `dark:` 变体都不用写 | 组件里没有地方可以「忘了加深色版」——深色模式的经典漏网之源 |
| SVG 图表跟着变 | 森林图 / 迷你 CI / 预测曲线用的是同一批变量。实测 CI 线颜色从 `rgb(21,128,61)` 变成 `rgb(74,222,128)` |
| 透明度语法继续可用 | 必须写成 `rgb(var(--c-x) / <alpha-value>)`；光写 `var(--c-x)`，`bg-brand/10` 会直接失效 |

踩到的三处硬编码残留（都已修）：森林图/预测/序贯的**圆点描边写死 `#ffffff`**（深色下变成白圈）、
详情页柱状条的 inline `background` 写死十六进制、弹层遮罩写死 `bg-[#3b2410]/25`（深色下压不住背景）。
它们都属于「主题没切干净」，肉眼只在特定页面才看得见——所以 `tests/theme.test.ts` 直接锁
「色板里不许再出现十六进制」+「两套变量逐一成对」+「按亮度断言深色真的深」。

默认值是**跟随系统**，存的是「选择」而不是算出来的结果——系统主题半夜切了，明天再打开要跟着换。
导出的结论卡固定按浅色画（canvas 不认 var()，且贴进文档时浅色更合适）。

### 6. 分日趋势（手写 SVG，F9 去掉 Recharts）

趋势图原本是唯一一处用图表库的地方。去掉之后：

| | 说明 |
|---|---|
| 体积 | 产物 JS **915KB → 573KB**（gzip 286KB → 187KB）；加入多臂与导入层后当前 **660KB / gzip 216KB** |
| 主题 | 线色直接引用 CSS 变量；图表库的内部样式要顺着它的 API 一个个塞，换主题时最容易漏 |
| 交互没丢 | 悬停取最近那天 + 十字准星 + 提示框（含当日样本量），冒烟里用 CDP 真发一次 `mousemove` 验过 |

几何（`值域 → 画布映射 → 按像素找最近那天`）抽在 `lib/trendGeom.ts`，7 条单测锁的正是
「写错了肉眼也看不出来」的那几类：纵轴画反、连续口径把金额画成负的、悬停取到隔壁那天。
刻度步长复用森林图那套 `niceStep`，两处口径一致。

### 护栏的三种状态（通过 / 未通过 / **不适用**）

三检查里「护栏」那一格原本只有两态，于是「这份数据没有退款列」被画成了绿色「通过」——
等于说「查过了，没问题」，而真相是没查。现在有第三态：`不适用`，配一句「退款率 缺列，未评估」。

| 数据情况 | 护栏格 | 护栏表格 | 决策 |
|---|---|---|---|
| 有退款列、未恶化 | 通过 | 正常数字，状态「未恶化」 | 不受影响 |
| 有退款列、显著恶化 | 未通过 | 正常数字，状态「显著恶化」 | 触发硬门禁 |
| **没有退款列** | **不适用** | 数值列全是「—」，状态「不可用（缺列）」 | 少一道门（代价可见） |

这条规则是 `docs/FAQ.md` §11b 的证据：[截图](screenshots/22-缺列-护栏不可用.png)。
第一版还踩了个更隐蔽的坑——三条护栏写成 `else if` 链，缺退款时投诉率与延迟**整行消失**，
比显示假 0 更难发现，是截图核对时才看出来的。

### 7. 实验设计（`#/plan`）——把生命周期往前补一格

之前所有屏都在「拿到数据之后」。而 PM 上岗第一个问题是「这个实验要跑多久 / 我的流量够不够」，
答不上来，实验就会在第 3 天被「看起来有效果」叫停。这一屏回答两个问题：

| 方向 | 输入 | 输出 |
|---|---|---|
| 我要测多大效应 | 基线转化率、想检出的相对提升、α、功效、日流量、分流比例 | 每组样本、总样本、**需要几天**、实际功效 |
| 我只能跑 N 天 | 同上，把「提升」换成「天数」 | **能检出的最小效应**（pp 与相对 %） |
| 连续指标 | σ 与要检出的绝对差值 | 每组样本、总样本、天数 |

三个刻意的取舍：

1. **样本量用二分反解自己的功效函数**，不套 Fleiss 近似公式。近似公式与真实功效差 1–3%，
   两者并存就会出现「按公式算的 n，跑完只有 78% 功效」。单测断言的是「`power(n) ≥ 0.8` 且
   `power(n−1) < 0.8`」——自洽、可验证，而不是「等于某个魔法数」。
2. **σ 不给默认值**。填别人的方差算出来的 n 只是看起来专业。
3. **加第三个臂的代价要算出来**：α 分摊到 2 次比较（每次 2.5%），每组样本 ×1.21、总流量 ×1.82。
   只说「多一组」，等于隐瞒成本。

### 8. 决策记录（详情页卡片 + 列表徽章）——把生命周期往后补一格

引擎给建议，人做决定。两者不一致时**理由必填**——否则这条记录只是把引擎结论抄了一遍，
三个月后完全看不出「当时是谁、为什么敢这么定」。

| 设计 | 为什么 |
|---|---|
| 快照冻结当时的差值 / p / n / 引擎结论 | 数据会变（重新导入、口径调整）。只存结论的话，永远无法还原「当时屏幕上写的是什么」 |
| 不一致才要理由，一致不必 | 强制每条都写会让人写「同意」，反而稀释了真正需要解释的那几条 |
| 「先搁置」永远算不一致 | 它根本不是统计结论，是人做的产品动作 |
| 列表页挂一个小徽章 | 决策是团队可见的状态，不该藏进详情页第 5 屏 |

实现是纯前端（localStorage，隐私模式回退内存），不假装有协作与权限——那条边界写在 README 里。

### 9. 云端协作（`#/cloud`）——只在有后端时才有内容

这一页是「边界」本身的可视化：

- **没有后端**：只显示「当前是本地模式」+ 三条启动命令 + 后端提供什么。
  不显示灰掉的用户表——灰掉的权限页会让人以为数据受控。
- **有后端**：登录/注册（第一个账号自动成为管理员）→ 六个 tab：数据集（一键上传当前数据源、重算并比对）、
  告警（四类，critical/warn/info）、决策审批（不能自审自批；驳回必写原因）、
  用户（改角色 / 停用，最后一个管理员不能被降级）、API Token（明文只显示一次）、
  审计日志（只追加，谁在什么时候动了哪条记录）。

## 二、为什么要这么设计

| 决策 | 理由 |
|---|---|
| 结论卡放在最上面、用最大字号 | 使用者 90% 的时间只想知道「能不能上」；细节按需展开 |
| 结论色 + 规则名同时出现 | 只说「不建议上线」会被问「凭什么」；`GUARDRAIL` 三个字母就是回答 |
| 差值用 pp（绝对百分点），不用相对提升做主视觉 | 相对提升会把 4%→4.2% 说成 +5%，容易误导；相对值降级到明细里 |
| 上浮色＝绿、下跌＝红 | 这是「决策语义」（好/坏），不是股价涨跌语义，所以不用红涨绿跌 |
| 真值对照默认折叠、但存在 | 敢把「引擎可能判错」放在页面上，才谈得上可证伪 |
| 复算做成按钮而不是自动 | 让「可复现」成为一个可被看见的动作 |
| 全部数字由浏览器端引擎算 | 没有服务端、没有模型参与，刷新/换机器结果一致 |

## 三、参考与取舍

参考了 GrowthBook（实验详情的信息层级）、Metabase（表格密度与数字对齐）、Vercel AI Chatbot / shadcn（面板、徽章、抽屉的克制风格）、Linear（深色下的层次与分割线）。

没有引入 shadcn/ui 与 Radix：本项目只需要 6 个原语（Panel / Badge / Button / Chip / Stat / Drawer），手写约 200 行比拉一整套依赖更可控，也避免组件库版本漂移。

## 四、工程上的四个坑（都已修）

1. **Tailwind v4 的媒体查询是 `(width>=48rem)` 区间语法**，Chrome < 104 直接不认，响应式整片失效（本地预览用的就是 Chrome 100 内核，一开始截图是错的）。→ 降到 **Tailwind v3.4**。
2. **Vite 默认 CSS 压缩器会把 `@media(min-width:640px)` 改写成区间语法**，即使 v3 也会被改坏。→ `build.cssMinify: 'esbuild'`。
3. **无头截图会拍到「加载中」**：`--virtual-time-budget` 会把定时器快进，但 fetch 是真实 I/O。→ 改用 CDP，轮询 `tbody tr` 出现后再截图（脚本 `.tmp_shot.mjs` 思路，已清理）。
4. **森林图横轴的步长与取值差 100 倍**（pp 口径）：步长按「百分点」算、起点按「百分数」取，于是一条横轴画出 **341 条网格线**。
   渲染出来是一片极浅的竖条纹底，**看着像刻意做的网格背景**，所以一直没被发现；同时刻度文字全被挤出画布，
   读者只看到 `0 / +1 / +2` 三条——数字"看着对"，是因为挤出去的那些根本没显示。
   发现路径是实验对比页：两张图同轴时那片条纹正好对齐绘图区，边界太齐才显得可疑。
   → 定标抽成 `src/lib/forestScale.ts`（纯函数），先统一换算到显示单位再算步长，目标 7 条刻度，
   `tests/forestScale.test.ts` 6 条把「条数 ≤ 12 / 刻度落在画布内 / 间隔均匀 / pp 与元标签不串」锁死。
   顺带暴露了第二个信号：冒烟脚本的「正文 ≥ 200 字」判据当时正被这 341 个重复刻度填充着，
   修完详情页正文从 6064 字降到 4878 字——**阈值型冒烟判据会被噪声喂饱**。

## 五、M3 补的三件事

1. **逐步代入**：引擎在生成证据时顺带产出 `calc: CalcStep[]`，UI 只做展示，不做二次计算——所以「页面上的数字」和「引擎的数字」不可能漂移。
2. **规则轨迹**：`Analysis.rules` 是 6 条规则 × (code, label, condition, detail, hit)，UI 只负责高亮 `reasonCode` 对应的那条。这样「为什么不是 ship」可以逐条追问。
3. **结论卡导出**：手写 SVG（880×宽，高度按理由行数自适应 552–600）→ `Image` → `canvas` 2 倍绘制 → `toDataURL('image/png')`。不引 html2canvas，避免体积与字体差异；中文用系统字体，在 Chrome/Edge 实测渲染正常。

> 真实模型验证：浏览器直连 DeepSeek 跑通（CORS 放行、4 次工具调用、10–12 个数字全部可溯源）。
> 第一次接真实模型时发现回答里直接显示 `**结论：…**`——模型用了 markdown 而 UI 当纯文本渲染，已补轻量渲染。
>
> 过程中抓到一个真 bug：护栏的推导最初用了「手工拼的假 PropTest」，导致页面上 z 显示 `0.0000`、CI 对称跨 0——数字看着合理但是错的。已改为直接复用 `GuardrailResult.propTest`，并加单测锁死（`z` 必须等于真实检验值、CI 必须包住点估计）。

## 六、M4：Agent 面板

第四个界面是右侧抽屉「问这个实验」，设计上有三个刻意的选择：

| 选择 | 为什么 |
|---|---|
| **默认规则模式、免密钥就能用** | 面试官打开链接时不会为了看 demo 去注册 API Key；也证明"不靠模型也能答" |
| **工具调用在回答上方可见、可展开看原始 JSON** | 让人亲眼确认"数字是从工具来的"，而不是模型编的 |
| **每条回答右上角一个审计徽章** | 绿＝N 个数字全部可溯源；红＝列出违规项（缺引用 / 无法溯源的数字），不藏起来 |

铁律在代码里的落点：

- 不许算数 → `askWithLlm` 只把工具结果回填给模型，`temperature=0.2`，`systemPrompt` 明确禁止心算
- 必须引用 → `violationsOf()` 检查有 cites 却无 `[E#]` 的回答并标红
- 证据不足就说不知道 → 口径陷阱意图（问 ARPU 但实验只测转化率）直接说"数据里没有这个口径"
- 不许编造历史 → 相似实验只能来自 `find_similar` / `list_experiments`

回答的渲染只支持模型真会用的三种写法——段落、`- ` / `1. ` 列表、`**加粗**`，其余一律当纯文本。
不引 markdown 库：体积不划算，而且「只渲染白名单语法」本身也是安全选择（不会执行任意 HTML）。
`[E6]` 会渲染成可点的证据 chip。

数字审计的实现（`src/lib/agent/audit.ts`）不是正则比对这么简单：
它把工具返回的所有数值（含 ×100 的百分数写法与绝对值写法）做成白名单，再**按文本里写的小数位数四舍五入后精确比对**——
这样 `0.623 → "0.62"` 能对上，而 `0.015` 不会蒙混过 `7.26e-7` 的 p 值。已知局限：符号不敏感（"下降 2.1pp" 与 `+2.1pp` 都算通过）。

## 七、M5：评测看板（`#/eval`）

这一屏是给"凭什么信你"准备的，顺序刻意安排成：

1. **六个数字**（准确率 / FPR / 分层 F1 / 幻觉数字率 / Agent 引用覆盖 / 负向漏判）——先给结论；
2. **混淆矩阵**——不藏错判，红格子在哪一眼能看到；下方那句总结是**现场算出来的**（按不一致的来源聚合），
   不写死"4 条"这种会随数据漂移的数字；
3. **按证据强度分桶**——这是最有信息量的一张图：p<0.001 准确率 98.4%（63/64），
   0.01–0.05 只有 **42.9%（3/7）**。它诚实地说明「准确率 93.3%」不是均匀分布的，边界上的实验本来就不可判；
4. **失败案例表**——8 条逐条可点开，进的是同一个证据链抽屉；
5. **分层检测 F1**（M11 新增）——四格（TP 12 / FP 1 / FN 3 / TN 104）+ P/R/F1 + 95% 区间 + 「放宽口径对照」
   （只要求交互显著时 F1 掉到 0.79、假阳性 1→5）。右侧写明为什么不拿 `decision === 'iterate'` 当预测值；
6. **置信度校准双口径**——标题右侧同时给 `ECE 20.0%（全量）· 5.0%（真值非零 70 个）`，并解释
   「0.95 以下那些点贴地板」不是后验算错，是精确 0 的真值被二值化成负类；
7. **Agent 问答自动评测**（M11 新增）——六格（幻觉数字率 / 引用覆盖 / 违规率 / 口径陷阱 / 路由准确 / 工具覆盖）
   + 按题目分组表 + 有问题的回答逐条列出；若设置页改过阈值，顶部出现黄条「这份评测已过期，重跑 npm run eval」；
8. **Ablation 双列**——规则模式 vs 智能模式，智能模式没跑就写"未运行"，不填数；
9. **口径与边界**——明确写"比的是与注入真值的一致性，不是线上业务效果"。

口径唯一源是 `src/lib/evaluate.ts`，`npm run calibrate`（命令行）和看板（浏览器）都调用它，
所以两边永远不会出现 93.3% 与 93.2% 这种分歧。FPR 分母刻意只用 `archetype=null`。

## 八、移动端（390px 实测后修的）

真实手机宽度下发现两个真问题，都已修：

1. **导航整块消失**——原来导航写了 `hidden md:flex`，手机上根本进不去评测看板。改成常显 + 紧凑尺寸，品牌副标题在 `<sm` 隐藏。
2. **表格被压成竖排文字**——列表的「主指标」列在 390px 下挤成「主 指 标」竖排，表头断行、徽章变形。
   给表格加 `min-w-[860px]`（详情 560、看板 720），窄屏改为**横向滚动**而不是压缩列宽。

结论：手机上「列表 → 详情 → 看板」可以走通，横向滚动可用；Agent 与证据链是抽屉，本来就占满宽度。

## 九、作品集页的截图（不是"贴上去就算"）

第一版把截图压到 1000px 塞进两列网格，结果每张只显示 400 多像素宽，界面里的字看不清——等于白放。

改法三条：
1. **内联 1600px 高清版**（JPEG q:v 3），缩略图与灯箱复用同一个 data URI，不重复占用体积；
2. 点任意截图 → 全屏灯箱，`Esc` / 点空白关闭，底部有「下载这张图」（文件名是 `01-实验列表.jpg` 这种可读名字）；
3. 悬停时右上角出现「点击看高清」，避免用户不知道可以点。

代价：单文件从 1.75MB → 4.2MB（9 张图 + 52s 视频，每加一屏多约 0.15MB）。这是值得的——图看不清的话，前面所有工作都白做。
