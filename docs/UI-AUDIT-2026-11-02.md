# 全量交互审查（2026-11-02）

> 目的：回答一个问题——**页面上有没有「点了没反应」「被挡住点不到」「禁用了但没说为什么」的控件。**
> 做法：`node scripts/audit_ui_controls.mjs`（真实浏览器，逐屏逐个点）
> 结论：**没有失效功能**。覆盖 9 个屏、**196 个可见控件**：179 个有反应、13 个是「当前态」
> （点它本来就不该变）、4 个按纪律跳过、**0 个无效**。
>
> 两轮共修掉两个真问题：① 选中态只靠颜色、没有 `aria-pressed`（读屏读不出当前选中项）；
> ② 实验设计页「带入基线」的下拉框用空值受控，选完永远弹回「选一个实验…」——
> 功能生效了但用户看不见自己选了什么。两处都是**静态读代码看不出来**的那类。

---

## 一、方法：为什么不能只读代码

四类问题里只有第一类能在代码里看出来：

| 问题类型 | 代码能看出? | 怎么发现 |
|---|---|---|
| 没绑 handler | 能（`onClick={() => {}}`，本项目 **0 处**） | 静态扫描 |
| 点了没反应 | 不能 | 真点 + 比对 DOM/hash/滚动/弹层签名 |
| 被遮挡（z-index / 遮罩） | 不能 | `elementFromPoint` 命中测试 |
| 禁用但没说明 | 不能 | 读 `disabled` 并人工看提示文案 |

脚本对每个控件做四件事：滚进视口 → 命中测试 → 点击 → 300ms 后比对签名
（`弹层数 / hash / scrollY / body.innerHTML 长度 / 深色类 / 激活态数量`）。任何一项变化即「有反应」。

**每个控件都单独重载路由后再点**：否则前一次点击留下的弹层会让后一次"看起来有变化"，
这是这类审查最容易自欺的地方。

## 三、结果

| 结论 | 数量 | 含义 |
|---|---|---|
| OK | 179 | 点击后有可见反应 |
| OK-CURRENT | 13 | 当前页导航 / 已激活 tab / 已选 provider / 品牌位：点它本来就不该有变化 |
| SKIP | 4 | 2 个改全局状态（人工确认）、2 个列表行按钮（由冒烟覆盖） |
| NO-OP | 2 → 修复后 0 | 见下 |

第二轮（加入「实验设计」屏后共 196 个控件）报出的 2 个 NO-OP 里，1 个是审查脚本的假象
（导航项清单漏了「实验设计」，停在那一页点它当然没变化），1 个是**真问题**：设计页
「从已有实验带入基线」的 `<select>` 用了 `value=""` 受控，选完立刻被重置回占位项——
数字确实填进去了，但下拉框上永远显示「选一个实验…」，用户会怀疑没生效。
改为记住选中项（并把「手改基线数字」视为放弃来源），现在是受状态的 `value={baselineFrom}`。

### 唯一的真问题：选中态只靠颜色

列表页的排序片「编号」被点时报 NO-OP，因为**它已经是选中态**——这本身不是 bug，但顺着查下去发现：

- `Chip`（筛选/排序/类型片）的选中态**只体现在 class 上**（`border-brand/60 bg-brand/15`），
  没有 `aria-pressed`；
- 详情页三个 tab（分层明细 / 护栏指标 / 计算过程）同样只有背景色，没有 `aria-selected` 或 `aria-pressed`。

对读屏和键盘用户来说，**这两组控件看不出当前选的是哪一个**。已修：

```tsx
// Chip：active 有定义时才输出属性，避免把「纯动作按钮」误标成开关
aria-pressed={active === undefined ? undefined : !!active}

// 详情页 tab
aria-pressed={tab === k}
```

修完后审查脚本也能凭 `aria-pressed` 认出「当前态」，不再误报。

### 人工/冒烟覆盖的 4 个

| 控件 | 处理 |
|---|---|
| 设置页「恢复默认」 | 默认态下 `disabled === true`（符合预期：没改过就没得恢复）；改 α 后变可用，并显示影响面 |
| 列表页「全部实验 120」筛选片 | 点它会清空筛选；审查时已处于无筛选态，属当前态 |
| 「加入对比 E001 / E002」 | 120 行共用同一 handler；冒烟场景「勾两个 → 对比这两个」真点过 |

### 顺带验证的端到端行为（不在审查脚本里）

- 改 α 0.05 → 0.2：影响面显示 **11 / 120 条结论会变**，准确率 **93.3% → 88.3%**，列表页同步更新；
- 原生 `<select>`（护栏口径）键盘可切换：`harm_and_practical → confirm_beyond_margin`；
- ⌘K → 输入 E029 → ↵ 直达详情；Esc 关闭；
- 三个 provider 按钮互斥切换后有选中样式。

## 四、审查脚本自己被骗了三次（写在这里，防下次重犯）

1. **重载后按旧索引找元素** → 数据异步渲染、DOM 顺序变了，报了一堆假 `GONE`。
   改成「tag + 文本 + 同名第几个」定位，并加 12 次轮询。
2. **元素在视口外** → `elementFromPoint` 返回 `null`，被判成"被遮挡"。改成先 `scrollIntoView` 再命中测试。
3. **原生控件用鼠标点**：`<select>` 在 headless 里点不开下拉、数字框只获得焦点、勾选框只改 property
   → 全被误判成"没反应"。改成：下拉用「聚焦 + 方向键」验证，输入类看焦点。

**教训**：审查工具本身也会说谎，而且它的谎比产品的 bug 更贵——因为它会让你去改没坏的东西。
