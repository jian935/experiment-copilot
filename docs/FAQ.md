# 面试 FAQ：会被问到的，以及当场能拿出来的

> 版本：2026-11-01（M13-H5）
> 用法：每条都是「一句话答案 → 证据（命令 / 文件 / 数字）→ 追问预案」。
> 原则：**能当场跑的数字才说，跑不出来的就说「这个我没测」。**

先给一句总纲，后面 12 条都是在撑它：

> 这个项目的赌注是「把不可验证的 AI 报告，换成可复算的决策」。
> 所以任何一条主张都必须有一个当场能跑的命令，或者一个当场能打开的文件。

## 一、为什么不用现成的（4 条）

### 1. 为什么不用 scipy / statsmodels？

**短答**：离线用 scipy 对齐，在线不用它——因为要跑在浏览器里，而且 scipy 把「口径」藏起来了。

**证据**：
- 运行时依赖只有 5 个前端包（`react` / `react-dom` / `lucide-react` / `clsx` / `tailwind-merge`），**统计零依赖**。
- scipy 不是被我「感觉对了」，是被**离线生成 fixture、单测逐位比对**：`tests/fixtures/scipy.json` 里 6 组两比例 z 检验（z 相对误差 <1e-6、p <1e-4）+ 5 组 SRM 卡方；t 分位数走不完全 Beta 的闭式，不用查表近似。
- 跑不起来的那条路更贵：Pyodide 光启动就是秒级、包体 3–5MB 起，而整个前端产物才 **660KB / gzip 216KB**；上后端则直接违背「零后端、可静态部署」。

**追问预案**：
- *「那你怎么证明自研的和 scipy 一致？」* → `npm test -- tests/stats.test.ts`，里面就是逐条比对；fixture 是 scipy 算的，不是我算的。
- *「scipy 有的你没有吧？」* → 对，我只要这条产品线用得到的：两比例 z、Wilson、Newcombe 差值 CI、卡方、t、bootstrap。**没用到的我宁愿没有**——每多一个分布函数就多一处没人检查的代码。

### 2. 为什么不用 GrowthBook / 现成的实验平台？

**短答**：它们解决的是「怎么把实验跑起来并分流量」，我要解决的是「这一个实验到底该不该上，以及凭什么」。

**证据**（只说我能确认的形态差异，不替别人总结技术细节）：
- 这类平台的核心是**流量分配 + 指标看板 + 部署形态**，通常需要后端与数仓接入；本项目是**零后端静态站点**，数据可以自带（JSON/CSV 导入，存 IndexedDB）。
- 本项目的产物是**一张可审计的结论卡**：证据链 9 条、每条能展开看逐步代入（① 转化率 → ② SE → ③ z/p → ④ Newcombe CI → ⑤ 阈值），并且能**同份数据一键复算、逐位比对**。
- 决策口径是我自己定义的六类（ship / no-ship / inconclusive / iterate / guardrail / srm），并且用**120 例已知真值**量化过：准确率 93.3%、FPR 5.0%。

**追问预案**：
- *「那你比它强在哪？」* → 不敢这么讲。它在「跑实验」这件事上比我完整一个量级；我在「单实验结论的可解释性与可复算」上做得更深。**如果团队已经有平台，我的价值是那层「结论官」，不是替换它。**
- *「它的统计引擎也很强吧？」* → 那要看它的文档，不是我替它总结。我能担保的只有自己这 340 条单测。

### 3. 为什么不用图表库？（Recharts 都被你去掉了）

**短答**：为了主题一致性和体积；而且这次换掉它，抓到一个潜伏的坐标轴 bug。

**证据**：
- 去掉 Recharts 后产物 JS **915KB → 573KB**（gzip 286KB → 187KB）。
- 全部颜色走 CSS 变量，所以深浅主题切换时 SVG 图表跟着换；图表库的内部样式要靠它的 API 一个个塞，换主题最容易漏。
- 顺带发现：森林图横轴步长按「百分点」算、起点按「百分数」取，差 100 倍，pp 口径的图**实际画了 341 条网格线**——渲染出来像刻意的网格底纹，刻度文字全被挤出画布，所以一直「看起来对」。定标抽成 `src/lib/forestScale.ts`，6 条单测锁条数/落点/间隔。

### 4. 为什么不让大模型直接算 / 直接给结论？

**短答**：让模型算数，就无法承诺可复现；而这个产品的全部价值就是可复现。

**证据**：
- 2200 条规则模式问答、**13546 个数字，可疑 0 个**（`npm run eval`）；引用覆盖率 100%（分母 1840，只算「有证据可引」的回答）。
- 真 DeepSeek 的 ablation（24 条问答 × 6 次）：引用覆盖 94.7–100%、可疑数字 0–0.6%、违规 0–8.3%。**注意：违规率和可疑率不是 0**，这就是为什么模型只做解释。
- 幻觉检测不是「感觉」：白名单 + 工具返回值比对。这套检测上线当天就抓到一个真 bug——白名单只收 number 不收字符串，把工具返回的 `mdeNowText: "0.63pp"` 判成幻觉（48 个误报）。

**追问预案**：
- *「模型到底做了什么？」* → 意图路由 + 选工具 + 把工具返回值讲成人话 + 追问。**它一个字都不算。**

## 二、数据可信吗（3 条）

### 5. 合成数据？那 93.3% 有什么意义？

**短答**：真实数据没有真值，无法量化「判对了没有」；合成数据的意义是**能给出已知答案**，并且种子固定、任何人可复现同一份。

**证据**：
- 120 个实验、6720 行日级明细、种子 `20261031`，生成器开源（`src/lib/simulate.ts`）；注入效应是明确的：正向 +2.0pp、负向 −1.5pp、异质仅新用户 +2.8pp、护栏族主指标 +1.8pp 且退款率 +0.8pp、SRM 分流 40/60。
- 四类结论完全一致才算对：准确率 **93.3%（112/120）**、null 误报 **5.0%（2/40）**、负效应漏判 **0%（0/30）**、正效应 **24/25**。
- 主指标口径与实验类型**正交**（每 6 个实验轮换 ARPU），否则连续口径只测了半个决策路径——这是 A3 阶段修掉的一个评测盲区。

### 6. 那不就是照着你的规则生成的数据？自证吧？

**短答**：这是最该被问的一条。自证的风险真实存在，所以我做了三件事把它压住。

**证据**：
1. **真值标签不由引擎定义**：类型在生成时就注入（positive / negative / heterogeneous / guardrail / srm），引擎只是去猜；猜错就记错，没有「事后调整口径」的空间。
2. **改口径必须同步改标注，不许改引擎去迁就**。典型例子：`heterogeneity` / `sequential` / `novelty` / `fwer` / `loss` 五个模块**都不参与 `decision`**——一旦让它们参与，历史 120 条真值标注全部作废。这是设计约束，不是实现方便。
3. **有真实数据的旁证**：真 DeepSeek 的 ablation 与规则模式同题对比（`docs/ABLATION.md`），以及 2000 次零效应 A/A 自校准（不是合成标注，是纯统计性质）。

**追问预案**：
- *「合成数据上 93.3%，真实数据会掉到多少？」* → 不知道，没测过真实业务数据，所以我不给这个数。我能说的是：**可能最先坏在哪**（见第 12 条）。
- *「那你不就是在优化一个玩具？」* → 统计部分是真实的（p 值、CI、序贯边界与权威实现对过），坏的是「数据像不像你们家」。这两件事得分开评。

### 7. 置信度校准 ECE 20%，是不是很差？

**短答**：那个 20% 是被「真值精确为 0」的样本污染的；只看真值非零的实验是 5.0%。两个口径我都摆出来。

**证据**：
- 全量 ECE **20.0%**；只看真值非零的 70 个实验 → **5.0%**。
- 原因是：真值为 0 时，任何中间置信度（比如 0.6）都必然算错——「精确 0」只能记成负类。所以全量口径衡量的是「有没有把 0 当 0」，不是「置信度准不准」。
- 评测看板上两个数同时展示，并写明分母（`docs/EVAL.md` §6）。

## 三、统计上站得住吗（5 条）

### 8. 为什么 p 落在 0.01–0.05 的实验只判对 3/7？

**短答**：这是 α=0.05 的必然代价，不是 bug；而且 7 个样本的区间宽到几乎没有结论。

**证据**：
- 临界区间准确率 **42.9%（3/7）**，我把它**当成一个单独指标公开**，而不是藏进总量里。
- p 在 0.01–0.05 时，效应量本身就在「可能是噪声」的量级；任何确定性规则在这段都会大量出错——换阈值只是把错误挪到别处，还会让 120 条标注全部重标。
- **不修的理由**：修它等于「改口径迁就引擎」。正确的做法是把这段单独报出来，让人知道「p=0.03 的结论要谨慎」。

**追问预案**：
- *「那你会怎么改？」* → 不改判定，改**呈现**：对这段加「证据不足，建议延长实验」的提示（现在的 `iterate` 就是这个角色），并把 MDE 与「还要跑几天」摆在旁边。

### 9. 序贯 / 新颖效应 / 多重比较 / 期望损失，为什么都不改 decision？

**短答**：因为它们改的是**读法**，不是**结论**；一旦参与决策，历史 120 条真值标注作废，评测就失去意义。

**证据**（四个都只出报告与建议）：

| 模块 | 实测 | 若参与决策的代价 |
|---|---|---|
| 序贯 | 每天看一次、看 7 次：naive 误报 **16.37%** → OBF **4.93%** | 阈值随「看了几次」变，决策不再是数据的函数 |
| 新颖效应 | A/A 误报 **4.8%（率）/ 6.4%（ARPU）**；第一版口径误报 12.0%/15.0%，写进文档 | 衰减检测本身要先信一个「按曝光量对半切」的假设 |
| 多重比较 | 全零族「至少一个显著」**99.79%**；naive 68 → Holm **53** | 清单开关会改写每个实验的结论 |
| 期望损失 | 门禁+净价值 **20.182** vs 频率派 15.696（+25.4% / +28.6%） | 净价值依赖 k 与 MMP 两个业务参数 |

**追问预案**：
- *「那用户到底听谁的？」* → 听 `decision`；四个模块给的是「换个口径会怎样」。这正是产品想说的：**同一个 p 值有四种读法，别只读一种。**

### 10. 期望损失里 k=1 会退化，那你这个模型是不是没什么用？

**短答**：对，k=1 时它**恒等于**「点估计 > MMP」，所以价值全在 k>1 与 MMP>0 这两件事上——我把这条恒等式写在面板上，而不是藏起来。

**证据**：
- 恒等式：`E[max(0,Δ)] − E[max(0,−Δ)] ≡ Δ̂`（k=1 时），单测按 1e-12 锁住。
- 真正起作用的是**两层结构**：硬门禁（SRM / 护栏 / 已确认负向）直接否决，不看净价值多大；异质只给「限定人群上线」的建议。
- 实测：裸规则净价值更高（23.978 vs 20.182），但它会为 **15 个**「护栏已恶化、主指标却大涨」的实验建议上线——实测退款率 **1.19% → 2.03%（1.71×）**。**门禁是约束，不是目标。**

### 10b. 去极值之后 p 从 0.051 变成 0.044，为什么不用这个更小的 p？

**短答**：因为截尾改的是**估计目标**，不是精度。截尾后的 p 检验的是「截尾后的 ARPU 差」，
一个不同的量；拿它当 ARPU 差的结论，等于换了题目再用新答案去答旧题。

**证据**（`npm run robust`，用户级粒度，每档 300 次模拟）：
- **原始口径守得住区间**：长尾从 κ=1 加重到 κ=200，delta method 的 95% 覆盖率始终在 **94.67%–96.67%**
  （名义 95%）。长尾的真实后果是「点估计飘、MSE 涨到 9 倍」，**不是「区间骗你」**。
- **截尾口径的区间塌了**：同一档下覆盖率 **33.67%**。所以面板上那一列叫 `p*` 不叫 p。
- **「截尾后更显著」是换假设换来的**：检出率 3.67% → **68.67%**，但同期覆盖率只剩 20.67%——
  涨的检出里多数是对「另一个目标」的检出。
- **它确实降 MSE**（4.89 → 1.23，降 75%）。所以它的用处是**点估计的稳健化 + 敏感性判断**，
  不是「第二次显著性检验」。面板给的是「结论会不会翻转」，不是「p 更小所以更好」。

**追问预案**：
- *「那什么情况下它真有用？」* → 两件事：① 看**单点杠杆**（删掉哪一行会改结论，精确重算，不依赖任何分位选择）；
  ② 看**集中度**（最重的 1% 曝光贡献多少收入）。这两个都不需要「截尾 p」就能回答「结论靠不靠少数人」。
- *「为什么内置数据上大多判 `stable`？」* → 因为数据是**日级聚合格子**（每行中位约 690 次曝光），
  1% 截尾只能去掉整格异常。粒度实验给的就是这个数：一行 1 人时截尾把偏差降 **54.9%**，
  一行 50 人时只剩 **3.0%**。要用户级截尾，就得导用户级明细——这条写在面板底部，不是隐藏项。

### 10c. 你不是说「不做权限」吗？怎么又做了后端？

**短答**：变的不是立场，是条件。当时的原话是「纯前端没有后端，做一个假权限不如不做」——
这句话里被反对的是**假**权限，不是权限。补上后端之后，假权限的前提消失了。

**做法**（`npm run server`，零依赖）：
- 真密码（scrypt 独立盐）、真会话（httpOnly Cookie）、真角色（viewer/analyst/admin，权限表只列真的会被执行的动作）；
- 决策**审批流**：分析师提交 → 管理员审批，**不能自审自批**，驳回必写原因；
- **审计日志**：append-only JSONL，谁在什么时候动了哪条记录；
- **API Token**：按角色发放，明文只显示一次，库里只存 sha256；
- **定时告警**：定时重算，结论从 ship 变 no-ship 立刻报——那是你不在看的时候发生的。

**仍然不做的三件**：SSO（没有 IdP 可对接，做一个假登录页就回到老路）、
分流 SDK / feature flag（边界在「数据已经在表里」）、Bandit（牺牲统计可解释性）。

**为什么没有后端也能用**：前端探测 `/v1/health` 1.5 秒，失败就静默退回本地模式，
权限/审批/审计这些入口**根本不出现**。GitHub Pages 上跑的就是这一版。

## 四、工程上（2 条）

### 11. 零后端怎么存数据？刷新不丢是怎么做的？

**短答**：三级降级 `IndexedDB → localStorage → memory`，存不下不静默。

**证据**：
- 结构化数据走 IndexedDB（`dataset.json` 已 1.7MB；塞 localStorage 要按 UTF-16 算 3.4MB，配额通常 5MB）。
- 降级顺序有单测：`pickBackend()` **真的写一次再删**，不只看 API 是否存在（隐私模式下 API 在但写会抛）。
- 配额超了不抛错，返回 `{ persisted: false, persistedNote }`，界面显示「本次导入只在当前标签页有效」——**不静默降级**。
- 冒烟真的验：导入 → `Page.reload` 硬刷新 → 数据仍在 → 切回内置 → 存档入口仍可点。

### 11b. 缺列时为什么不直接填 0？

**短答**：因为「0」是一个结论，「没有」不是。把缺失填成 0，表格会写出「退款率 0.00% → 0.00%，未恶化」——
读者读到的意思是「查过了，没问题」，而真相是「没数据」。**这比不显示更糟。**

**证据**：
- 归一化确实会把缺失填 0（下游类型不变、不会崩），所以「缺过」这件事必须在解析阶段单独记下来（`missingColumns`）。
- 修的过程中还踩到一个更隐蔽的坑：第一版把三条护栏写成 `if (缺退款) … else if (有数据) { 三条一起算 }`，
  于是缺 refunds 时**投诉率与延迟整行消失**——表格只剩一行，比显示假 0 更难被发现。是截图核对时才看出来的。
  现在三条各自独立，单测断言「缺一列时另外两条仍在评估」。
- 代价说清楚：缺 refunds 就少一道硬门，决策会变（单测里那个实验从 `no-ship` 变回可上线）。
  这个代价必须可见——所以它同时出现在三检查（不适用）和证据链（未评估）里。

### 12. 如果给你真实数据，哪里会最先坏？

**短答**：四个地方，按我预计的先后顺序。

| 顺序 | 会坏的地方 | 原因 | 现在的处理 |
|---|---|---|---|
| 1 | **护栏指标** | 真实团队未必有 refunds / complaints / latency 三列；缺列就没有护栏 | **缺列就写缺列**：导入时把整列缺失记进 `missingColumns`，护栏表格里那一行显示「—」与「不可用（缺列）」，三检查显示「不适用」、且它不参与决策。有单测 + 冒烟盯着（[截图](screenshots/22-缺列-护栏不可用.png)） |
| 2 | **分层** | 真实数据可能没有 tenure / device；或者切完每格样本不足 | 缺字段整行归入单层，仍可分析（只是无分层） |
| 3 | **稳健标准误 / CUPED** | 稳健 SE 要从「格子间离散」估，**每臂至少 4 个格子（合计 8 个）**才启用；只有总和数据时会退回 z 检验 | `cupedAdjust` 返回 null → 走 z 检验，证据链写明用的哪个口径 |
| 4 | **真值** | 真实数据没有 groundTruth，评测看板的准确率/ECE 全部失效 | 导入时 `groundTruth=false`，看板只展示不需要真值的指标 |

**追问预案**：
- *「那你怎么知道第 1 条不会更糟？」* → 我不知道。这是按依赖关系排的：护栏缺失是**功能消失**，不是数字算错；而算错比消失更危险，所以我把「缺数据时不许编」写成了硬约束。

## 五、如果只记住三句

1. **不可复现的结论不算结论**：同份数据一键复算、逐位比对，模型一个字都不算。
2. **先做硬前置检查，再谈显著性**：SRM / 样本量 / 护栏在 p 值之前。
3. **每个口径都写了它自己会坏在哪**：`docs/METHODOLOGY.md` 里每个选择都带代价，包括「Newcombe 在 p≈0.5、n=30 时覆盖率 90.8%，比 Wald 的 94.8% 更差」这种对自己不利的实测。
