# 数据需求清单（给数据提供方看）

> 项目：Experiment Copilot（实验结论官）
> 用途：A/B 实验分析演示 + 评测
> 原则：**只要聚合计数，不要用户明细**（无 UserID / 手机号 / 订单号 / 精确个人金额）

---

## 0. 一句话

我需要的是：**每个实验、每个变体、每天、每个分层下的「曝光数 / 转化数 / 汇总金额」**，
不是一行行的用户行为日志。

- 最小可用：**1 个实验 × 2 个变体 × 1 个二值指标 × 7 天**
- 理想：**6–10 个实验**，覆盖"无效果 / 正效果 / 负效果 / 某分层才有效 / 分流不均"

---

## 1. 表 A：实验清单（experiments）

一行一个实验。CSV / Excel 均可。

| 字段 | 必需 | 类型 | 说明 | 示例 |
|---|---|---|---|---|
| `exp_id` | ✅ | 文本 | 实验编号，**可脱敏** | `E001` |
| `exp_name` | 否 | 文本 | 实验名，**可脱敏** | `实验1` |
| `hypothesis` | 否 | 文本 | 一句话假设 | `新结算页能提升支付转化` |
| `start_date` | ✅ | 日期 | 开始日期 | `2026-09-01` |
| `end_date` | ✅ | 日期 | 结束日期 | `2026-09-14` |
| `variants` | ✅ | 文本 | 变体名，逗号分隔 | `control,treatment` |
| `traffic_split` | 否 | 文本 | 分流比例 | `50/50` |
| `primary_metric` | ✅ | 文本 | 主指标名 | `支付转化率` |
| `primary_metric_type` | ✅ | 枚举 | `binary` / `continuous` / `ratio` | `binary` |
| `guardrail_metrics` | 否 | 文本 | 护栏指标，逗号分隔 | `退款率,投诉率` |
| `decision` | 否 | 枚举 | 当时的决策 | `ship` / `no-ship` / `iterate` / `inconclusive` |
| `decision_reason` | 否 | 文本 | 当时为什么这么定 | `主指标显著为正，护栏无恶化` |
| `true_lift` | 否 | 数字 | **仅当有可信真值**（如上线后 holdout 的长期效应） | `0.021` |

---

## 2. 表 B：每日 × 变体 × 分层（daily_metrics）

一行 = 一个实验 × 一天 × 一个变体 × 一个分层组合。**这是核心表。**

| 字段 | 必需 | 类型 | 说明 | 示例 |
|---|---|---|---|---|
| `exp_id` | ✅ | 文本 | 对应表 A | `E001` |
| `date` | ✅ | 日期 | 日期 | `2026-09-01` |
| `variant` | ✅ | 文本 | 变体 | `control` |
| `segment_device` | 否 | 文本 | 设备 | `iOS` / `Android` / `Web` |
| `segment_tenure` | 否 | 文本 | 新老 | `new` / `old` |
| `segment_channel` | 否 | 文本 | 渠道 | `organic` / `paid` |
| `exposures` | ✅ | 整数 | 进入实验的**去重人数** | `10234` |
| `conversions` | ✅ | 整数 | 达成主指标的人数（二值指标用） | `512` |
| `metric_sum` | 否 | 数字 | 连续指标的**总和**（如 GMV） | `238900.5` |
| `metric_sq_sum` | 否 | 数字 | 连续指标的**平方和**（算方差用） | `...` |
| `metric_count` | 否 | 整数 | 有值的样本数 | `10234` |
| `refunds` | 否 | 整数 | 退款数（护栏） | `31` |
| `complaints` | 否 | 整数 | 投诉数（护栏） | `5` |
| `latency_p95_ms` | 否 | 数字 | P95 延迟（护栏） | `820` |

### 连续指标拿不到 `metric_sq_sum` 怎么办
三个替代，任选其一：
1. 给每组的 **均值 + 标准差 + 样本量**；
2. 只给 **二值指标**（先跑通转化率，连续指标以后再说）；
3. 给**脱敏后的每人金额**（只有金额、没有身份）——但这属于明细，非必要不推荐。

---

## 3. 我不需要什么（明确排除）

- ❌ UserID / 设备 ID / 手机号 / 邮箱 / 订单号
- ❌ 任何可反查到个人的字段
- ❌ 原始行为日志（点击流、埋点明细）
- ❌ 金额精确到个人的记录
- ❌ 公司名、项目代号、未公开的业务指标名（可用"实验1""指标A"代替）

> 只要"每组的计数和汇总"，就足够做 SRM、显著性、置信区间、分层与护栏分析。

---

## 4. 格式与交付

- **格式**：CSV（UTF-8）或 Excel；一行表头；日期统一 `YYYY-MM-DD`
- **文件**：`experiments.csv`、`daily_metrics.csv`（或一个 xlsx 两个 sheet）
- **命名**：不要出现公司/项目真名，用 `E001`、`指标A`
- **交付**：直接放本地 `.local/` 目录（已 gitignore，不会进公开仓库）

---

## 5. 合规提醒（重要）

- 如果数据来自实习公司/业务方：**必须先获得明确授权**，并确认"可用于个人作品集展示"。
- 拿不到授权就别用；用合成数据 + 公开数据集同样能完成项目。
- 公开仓库里**只放生成器/脱敏样本**，不放原始导出文件。
- 展示时用"某电商业务""实验 E001"，不出现可识别的公司信息。

---

## 6. 拿到数据后我会先做 6 项体检

1. 行数与日期连续性（有没有缺天）
2. 变体是否一致（同一实验的 variant 集合）
3. `exposures > 0`、`conversions ≤ exposures`
4. 分流比 vs 实际曝光（SRM 初判）
5. 缺失值比例（分层字段缺失是否可以接受）
6. 主指标口径是否可复算（用汇总反推转化率，和业务方给的数字对一下）

体检不过的会先跟你确认，不会直接拿去算。

---

## 7. 如果拿不到真实数据（完全可接受）

| 替代 | 作用 |
|---|---|
| **合成数据生成器**（固定种子、开源） | 已知真值，用于评测"决策准不准" |
| **公开数据集 Cookie Cats A/B** | 真实二值指标（retention_1 / retention_7），做一次"真实数据 sanity check" |
| 其他公开 A/B / uplift 数据集 | 增加真实感，但不作为主评测 |

> 真实数据解决"像不像真的"，合成数据解决"对不对"。两者不冲突。

---

## 8. 需要你确认的 3 件事

1. 数据来源是否**允许用于公开作品集**（哪怕脱敏）？
2. 能否提供**实验当时的决策记录**（ship / no-ship / iterate）？
3. 大概能拿到**几个实验、多长时间**？

有这 3 个答案，我就能判断是"真实数据为主"还是"合成 + 公开数据为主"。
