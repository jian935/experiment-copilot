# 全量盘点与旗舰化扩展清单（v2）

> 2026-11-01 第二次全检。本文取代 `docs/ROADMAP.md`（v1）成为**主计划**。
> 检视范围：`docs/BLUEPRINT.md`（承诺）、`docs/EVAL.md`（已知局限）、`docs/UI.md`（界面承诺）、
> `src/**`（实现）、`scripts/**`、`tests/**`。
> 铁律不变：**每加一个统计量必须有单测对齐权威实现**；**改口径不改引擎去迁就**；**对外数字只引实测值**。

## 0. 一句话结论

引擎与"可审计"叙事已经立住（96.7% 决策准确率 + 贝叶斯层 + 9 工具 Agent + 导入），
但**离"旗舰"还差三类东西**：

1. **统计深度**：CUPED / 序贯 / 连续指标 / 非劣检验 / Bootstrap —— 蓝图 §8 写了 8 个方法，落地了 5 个。
2. **产品完整度**：设置页（蓝图第 6 屏缺失）、口径字典（蓝图 §7.3 缺失）、Trace 面板（蓝图 §11.2 缺失）。
3. **工程与交付闭环**：CI 防回归、Pages 上线、覆盖率门槛、数据变大后的性能。

下面按「已有什么 → 承诺差什么 → 还能加什么 → 先做什么」四段展开。

| 模块 | 已实现 | 落点 |

## 三、旗舰化扩展清单（能落地的全列）

记号：**★=旗舰差异化（别人没有/难抄）**；成本 小/中/大；前置 = 依赖别的项。

### A. 统计引擎（最硬，简历最值钱）

| # | 项目 | 价值 | 落点 | 验收 | 成本 | 前置 |
|---|---|---|---|---|---|---|
| A1 ★ | **CUPED 方差缩减** | 行业公认的 A/B 高级技巧（Booking/Netflix 标配），"同样样本量更快出结论"；能讲清协变量回归调整 | `simulate` 加 pre-period 列 → `stats::cupedAdjust` → `decide` 出 CUPED 前后对比证据 | 单测：方差缩减比例符合理论；CUPED 后点估计不变、SE 变小；A/A 下缩减≈0 | 大 | 数据加 pre-period |
| A2 ★ | **序贯检验 / always-valid p**（mSPRT 或 O'Brien–Fleming alpha spending） | 防 peeking——真实团队每天都在偷看；给出"每天看一次需要多严的阈值" | `stats::sequential*` + 详情页"窥探校正"开关 + 逐日边界图 | 单测：α 在多次窥探下仍受控（模拟 A/A 1000 次，错误率 ≤5%） | 大 | — |
| A3 ★ | **连续指标（ARPU/GMV）接入决策** | 蓝图 §7.2 要求；当前只有二值转化率，真实场景一半指标是连续/金额 | `DailyRow` 加 revenue_sum/sq_sum → Welch + Bootstrap CI → 决策纳入 → 新增连续指标原型 | 单测：Welch 与已知例子对齐；Bootstrap CI 固定种子可复现 | 大 | — |
| A4 | **非劣检验做护栏**（margin 预设） | 蓝图 §8 明确要求；当前"阈值判定"统计上不严谨，被问"为什么是 0.4pp"答不硬 | `stats::nonInferiority` → 护栏改正式检验 | 单测：margin 内判通过、外判恶化；与单侧检验等价性 | 中 | — |
| A5 | **Bootstrap（10k，固定种子）** | 蓝图 §8 要求；比值指标（如人均订单数）的稳健 CI 只能靠它 | `stats::bootstrapCI` | 单测：同种子两次结果逐位相同 | 中 | — |
| A6 | **多实验 FWER / 跨维度多重比较** | 蓝图 §5 P2；看 120 个实验时"总有一个显著" | `stats::holm/bonferroni` + 列表页"全局校正"开关 | 单测：FWER 模拟受控 | 中 | — |
| A7 ★ | **新颖效应 / 效应衰减检测** | 7 天趋势里能看"前 3 天有效、后 4 天消失"，这是真分析师会问的 | `decide` 加逐日效应回归/前后半段对比 → 趋势图 + 证据 | 单测：注入衰减的合成数据能被识别 | 中 | 数据加衰减原型 |
| A8 ★ | **A/A 检验与引擎自校准** | 证明"引擎在无效应时不乱报"的最好证据——比准确率更有说服力 | 生成器加 `aa` 原型 → 跑 1000 次 A/A 统计误报率 | 报告：A/A 误报率 ≈ α（实测值写入文档） | 中 | — |
| A9 | **CI 覆盖率模拟单测** | 蓝图 §8 明列要求（94–96%）；现在只有"区间包含点估计" | `tests/stats.test.ts` 加 1000 次模拟 | 覆盖率落在 94–96% | 中 | — |
| A10 | **分位数指标检验**（P95 延迟的分位数而非均值比较） | 当前 P95 是拿均值比均值，统计上不成立 | `stats` 分位数 bootstrap | 单测：分位数 bootstrap CI 覆盖 | 中 | A5 |

## 六、落地时的三条纪律

1. **数字纪律**：任何写进 README / 作品集 / 简历的数字，必须是 `npm run calibrate` 或评测脚本的**当场输出**；未跑就写"待实测"。
2. **单测纪律**：新统计函数必须对齐权威实现（scipy / 闭式解 / 已知例子），并在 `tests/` 留断言。
3. **口径纪律**：评测口径唯一源是 `src/lib/evaluate.ts`，命令行与看板共用；新增指标只加不改口径，改口径要同步改 EVAL.md 与文档。
