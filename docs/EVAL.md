## 2. 决策规则（v1）

按优先级：

1. **SRM**：`p<0.001` 且 `相对偏差>2%` → `inconclusive`
2. **硬护栏（仅退款率）**：`差值>0.4pp` 且 `p<0.01` → `no-ship`
3. **主指标显著负向**：`p<0.05` 且 `diff<0` → `no-ship`
4. **异质**：交互 `p<0.01`，且一个分层 `BH q≤0.1` 显著为正，另一个分层 `p>0.1` 且效应 `<0.5×` 显著分层 → `iterate`
5. **不显著**：`p≥0.05` → `inconclusive`
6. 其余 → `ship`

**为什么只让退款率做硬护栏**：投诉率基线只有 0.12%，随机波动会产生大量假阳性；P95 延迟在 v1 只展示不判定。退款率基线 1.2%，0.4pp ≈ 相对 +33%，是"实质恶化"的合理阈值。

## 3. 校准结果（120 例，真实决策 vs 引擎决策）

```
true\pred     ship   no-ship  iterate  inconclusive
ship            24       0        1         0
no-ship          0      30        0         0
iterate          0       0       12         3
inconclusive     2       2        0        46
```

| 指标 | 数值 |
|---|---|
| **决策准确率** | **93.3%**（112/120） |
| null 误判为 ship（FPR） | 5.0%（2/40） |
| 正效应漏判（FNR） | **4.0%（1/25）** |
| 负效应漏判（FNR） | 0.0%（0/30） |
| 异质识别 | 80%（12/15） |
| SRM 识别 | 100%（10/10） |
| 护栏拦截 | 100%（15/15） |
| 临界桶 `0.01 ≤ p < 0.05` | 42.9%（3/7） |

> **为什么准确率从 96.7% 降到 93.3%**（2026-11-01，M10）：
> 之前的 96.7% 有一部分是靠**过于乐观的标准误**换来的。M10 做了两件事——
> ① 给数据加上真实的按臂基线漂移（两臂是不同用户，天然不同）；
> ② 主指标标准误改用格子级稳健估计，不再假设 i.i.d.。
> 结果是：同一批数据上朴素口径准确率 91.7%、**null 误报率 17.5%**（名义 5%）；
> 换稳健标准误后准确率 94.2%、误报率 10%；再加 CUPED 准确率 93.3%，
> 而**大样本 A/A（2000 次）实测总误报率 6.35%**（率口径 6.20%±1.49pp、连续口径 6.50%±1.53pp，均在名义 5% 的区间内）。
> 换句话说：准确率降了 3.4 个点，换来的是误报率从失控回到标定值附近——这是诚实的代价，不是退步。
> 注：`91.7% / 94.2% / 17.5% / 10%` 是 M10 关闭/打开稳健标准误那一次对照实验的数字（当时数据集还没有连续口径），
> 保留它们是为了说明归因；曲线上的当前值以本节表格为准。

### 剩下 8 个不一致是什么

| 类别 | 条数 | 说明 |
|---|---|---|
| null 假阳性 | 4 | 2 判 ship、2 判 no-ship（p 在 0.0015–0.047）。α=0.05 下本就该发生的第一类错误 |
| 异质实验漏判 | 3 | 交互不显著即判 inconclusive（E020/E056/E062，p=0.063–0.159）。这是「证据不足就说不算异质」的代价 |
| **正效应被判 iterate** | **1** | **E029**：主指标 p=3.6e-7、ARPU +1.23 元（+37%），但分层交互 p=0.004（新用户 +1.81 元 / 老用户 +0.66 元）→ 规则要求「分层复查」 |

E029 值得单独说：造数据时新旧用户的真值**完全相同**（各 +2pp），所以这是抽样噪声撞上了
「交互显著就要求分层复查」这条规则。我们**没有**为了让这条变对去放宽交互阈值——
该规则在 A/A 上是保守的（实测异质误判 0.4%–0.8%，见 §4b），而它在 15 个真异质实验里能抓到 12 个。
把它调松，等于用 1 条噪声换掉 3–5 条真异质的召回。这条取舍写进单测（`tests/evaluate.test.ts` 里锁死了
「就是这 1 条、就是 E029、原因可查」），防止以后有人悄悄调阈值把它变绿。

## 3b. 两条主指标口径走的是同一套规则

主指标可以是转化率，也可以是 **ARPU**（`metricType='continuous'`）。决策规则完全不变——
SRM → 护栏 → 负向 → 异质 → 不显著 → 正向，六条的顺序与阈值一模一样，
只有「主指标怎么检验」这一层不同：

| 环节 | 率口径 | 连续口径 |
|---|---|---|
| 点估计 | `p̂ = c/n` | `Σrevenue / Σexposures` |
| 标准误 | 格子级稳健 SE（φ≈1.41） | delta method + 格子聚类方差（Welch–Satterthwaite 自由度） |
| 区间 | Newcombe → 稳健 z 区间 | t 分位（df≈47–54） |
| 贝叶斯 | Beta-Binomial | 正态后验 |
| 护栏 | 率口径 | **率口径（不跟着主指标变）** |

**护栏为什么不跟着变**：退款率、投诉率本身是比例，用 ARPU 的方法检验它们毫无意义；
而「ARPU 涨了但退款率也涨了」恰恰是最需要拦的组合。这条在代码里是硬约束（`guardrails` 恒走率路径），不是默认值。

**口径与实验类型必须正交**（`tests/simulate.test.ts` 锁住）：如果 ARPU 实验只落在某些真值类型上，
「连续口径的检出率 / 误报率」测的就是半个决策路径。第一版就是这个错
（`i % 3` 撞上 6 个一循环的类型，ARPU 只剩 negative + srm），改成按 6 个一块轮转后
40 个 ARPU 实验覆盖全部 6 类，其中 **11 个是有真实正效应的**（positive 类 25 个里 11 个走 ARPU）。

**降级路径有测试兜底**：声明 `continuous` 但数据里没有 `revenue` 时，引擎退回率口径，
`metricFallback` 写明原因，界面上显式提示——不静默、也不假装。

## 4b. A/A 自校准（`npm run aa`，2000 次零效应实验）

比"准确率 93.3%"更硬的一类证据：真值就是 0，引擎报了多少次显著一目了然。
生成器用同一套 `buildExperiment`，只是两臂同分布（`archetype = null`），一半率指标、一半 ARPU。

| 指标 | 实测（n=2000） | 名义值 |
|---|---|---|
| 总误报率（非 inconclusive） | **6.35%**（±0.55pp） | α = 5.00% |
| 正向误报 ship | 2.70% | α/2 = 2.50% |
| 负向误报 no-ship | 3.20% | α/2 = 2.50% |
| iterate | 0.45% | —（分层规则是 α 之外的一层判定） |
| SRM 误报 | **0.00%** | 0.10% |
| 硬护栏误报 | 0.00% | 0.50%（单侧） |
| 贝叶斯 P(B>A) 均值 | 0.4994 | 0.5 |
| P(B>A) > 0.95 比例 | 5.30% | ≈5% |

每臂平均 19,605 样本、7 天、seed `20261101`。报告写入 `data/aa_report.json`。

**按主指标口径分开（同一批实验，必须分开看）**：

| 口径 | n | 误报率 | ship / no-ship | P(B>A)>0.95 |
|---|---|---|---|---|
| 率口径（转化率） | 1000 | 6.20% ± **1.49pp** | 27 / 31 | 4.60% |
| 连续口径（ARPU） | 1000 | 6.50% ± **1.53pp** | 27 / 33 | 6.00% |

两个都在名义 5% 的 95% 区间里（下界 4.71% / 4.97%），没有系统性方向；
合计 6.35% 比 5% 高约 2.5 个标准误，多出来的那一小部分主要是分层规则——它是在 α 之外
再叠的一层判定（A/A 下 0.45%），所以「总误报」天然略高于 α 本身。这个偏差我们不藏：
要么承认它，要么把分层门槛提到 α 以外去，后者会同时丢掉真异质的召回（见 §3 的 E029 取舍）。

**同一个引擎在三种标准误口径下的 A/A 误报率（2000 次，`npm run cuped`）**：

| 口径 | 率口径 | 连续口径 |
|---|---|---|
| i.i.d. 二项标准误 | **9.70%** | 6.10% |
| 格子级稳健标准误 | **6.20%** | 6.10% |
| 稳健 + CUPED | 6.20% | 6.50% |

**这张表最有价值的一行是「连续口径 6.10% → 6.10%」**：delta method + 格子聚类方差本来
就是聚类标准误，所以「换成稳健 SE」对它毫无额外收益。也就是说——
**修好误报率的是稳健标准误，而它只对率口径有意义；CUPED 两口径都不破坏校准。**
把两件事混成一句「我们做了稳健 SE」，就等于没说清楚到底谁在起作用。

## 4c. CUPED 方差缩减（`npm run cuped`）

| 指标 | 全部 120 | 率口径（80） | 连续口径（40） |
|---|---|---|---|
| 前后周期相关系数 ρ（中位） | 0.271 | 0.261 | 0.305 |
| 过离散因子 φ（中位） | 1.24 | **1.41** | 1.00（固定） |
| 方差缩减（中位） | **7.24%** | 7.00% | **10.14%** |
| 方差缩减（均值 / p90） | 9.28% / 19.71% | 8.48% / — | 10.89% / — |
| 格子数 | 56（7 天 × 2 端 × 2 人群 × 2 变体） | 同 | 同 |

连续口径的缩减更大且 ρ 更高（0.305），因为**前周期收入与当期收入的相关性比转化数更稳**：
转化数在低基数下是稀疏计数，收入是连续量。φ 固定为 1 也是同一个原因——
ARPU 没有「有效样本量」这一说，把 φ 硬套上去反而会把区间弄错。

**归因必须分开讲**（否则就是把标准误的功劳算到 CUPED 头上）：
- 修好误报率靠的是 `seMode = 'robust'`（率口径 9.70% → 6.20%）；
- CUPED 的功劳是**在区间已经诚实的前提下再收窄**（中位 7.24%，且不破坏校准：6.15% → 6.35%，在噪声内）；
- 在本数据集的效应量（±1.5~2.8pp、±0.4~1.2 元、每臂 2 万）下，三种口径都 100% 检出 25 个真实正效应，
  所以 CUPED 的价值体现在**区间宽度 / 等价样本量**（方差降 r ⇔ 样本量降 r），不在检出数——这点如实写明，不夸大。

## 4d. 分层检测 F1（E1，`npm run eval`）

**为什么单独评检测器**：决策是 SRM → 护栏 → 负向 → 异质 → 不显著 → 正向的**合取链**。
一个真异质实验可能被更早的规则拦走，从决策上看是"错"的，但异质检测器其实根本没机会表现。
所以要评的是 `analysis.heterogeneity`，不是 `decision === 'iterate'`。

真值 = `archetype === 'heterogeneous'`（生成器注入「新老用户真值不同」），共 15 个。

| 口径 | TP | FP | FN | TN | precision | recall | F1 |
|---|---|---|---|---|---|---|---|
| **实际检测器**（交互显著 ∧ 一个分层显著为正 ∧ 另一个无效） | 12 | 1 | 3 | 104 | 0.923 | 0.800 | **0.857** |
| 放宽（只要求交互 p < 0.01） | 13 | 5 | 2 | 105 | 0.722 | 0.867 | 0.788 |

95% CI（对实验重抽样 1000 次，固定 seed）：**0.667 – 0.970**。

三条要读出来的东西：

1. **点估计 0.857 过了蓝图 §10.2 的 0.8，但区间下界只有 0.667。** 正例只有 15 个，动一条 F1 就跳 3–5 个点。
   所以对外写「F1 0.857（15 个正例，95% CI 0.67–0.97）」，不单写「F1 ≥ 0.8 达标」。
2. **放宽口径反而更差（0.788 < 0.857）**：召回只多 1 条（12→13），假阳性从 1 涨到 5。
   这直接回答了一个设计问题——「一个分层显著为正、另一个无效」这层合取不是多余条件，是净收益。
3. **3 条漏检 + 1 条误报都能点名**，不是"黑箱里差一点"：
   | 实验 | 交互 p | 情况 |
   |---|---|---|
   | E020 | 8.5e-13 | 交互极显著，但**两个分层都显著**（flat 分层为空）→ 合取不满足，判「不算异质」 |
   | E056 | 1.08e-2 | 差一点（阈值 0.01） |
   | E062 | 0.283 | 样本噪声把真异质埋了 |
   | E029（误报） | 4.0e-3 | 真值是 positive，但交互显著。**这就是 §3 里那条「正效应被判 iterate」的实验**——两个指标指向同一条数据，互相印证 |

## 4e. Agent 问答自动评测（D6，`npm run eval`）

题库 15 道 × 120 个实验（「收入拆解」只在 40 个 ARPU 实验上问）= **1720 条问答**。
规则模式、无需 Key、**完全确定性**（同输入同输出），所以能进 CI 与基线比对。

| 指标 | 实测 | 说明 |
|---|---|---|
| **幻觉数字率** | **0.00%**（0 / 10177 个数字） | 回答里出现、但引擎与工具从未返回过的数字 ÷ 数字总数 |
| 引用覆盖率 | 100.0%（分母 **1480**） | 有 240 条回答本来就没有证据可引（如「有哪些实验被拦截」），不计入分母 |
| 违规率 | 0.00% | 缺引用或出现幻觉数字 |
| 口径陷阱识别 | 100.0%（分母 80） | 主指标是转化率却被问 ARPU 时，说清主 / 副指标 |
| 意图路由准确 | 100.0%（分母 1080） | 15 道题里 9 道有期望意图 |
| 工具覆盖 | **12 / 12** | 每个工具都被至少一道题触达 |

**为什么分母要写出来**：引用覆盖率若把「本来就没有证据可引」的回答算进分母，会被稀释，
看起来像 Agent 经常不引用——那不是它差，是分母挑错了。240 条这类回答被排除，1480 才是真分母。
同理，口径纪律的分母只取「主指标是转化率却被问 ARPU」的 80 条，ARPU 实验上的同一道题是正经问题，不该混进来。

**接进自动评测的当天就抓到一个真 bug**（在判定器里，不在回答里）：
规则模式的「还要跑几天」冒出 **48 个无法溯源的数字**（0.63 / 0.68 / 20）。
查下来是 `audit.ts` 的白名单**只收 number、不收字符串**——工具返回的 `mdeNowText: "0.63pp"` 是格式化文本字段，
回答照抄它是**合规**的（system prompt 第 6 条就是这么要求的），却被判成幻觉；另外 `20%` 是模板里的分位数常量，没进常量表。
修完后 1720 条回答的可疑数字归零。

> 这条比数字本身更值得记：那个 bug 在人工 ablation 里躺了很久，因为「规则模式不可能编数字」听起来太合理，
> 没人去查。**指标不自动跑，它就会停在「我以为它是 0」。**

## 4f. 回归基线 + CI（E6 / G1）

`eval/baseline.json` 记 **82 个指标** + **数据指纹**（去掉 `generatedAt` 后对 experiments + daily 求 sha256 前 16 位）。

- `npm run eval -- --write` 写基线；`npm run eval:check` 比对，任何漂移 `exit 1`；
- CI（`.github/workflows/ci.yml`）：typecheck → test → 基线比对 → **重建数据后再比对**（证明同代码出同数据）→ A/A 200 次冒烟（`--dry`，不覆盖 2000 次的正式报告）。

比对器自己有 **10 条单测**（`tests/evalBaseline.test.ts`）：能抓到「一个实验判错」（准确率动 0.83pp）、
不会被 1e-15 的浮点噪声误报、新增/消失指标都报、字符串字段变化也报。
**检查器不测，等于没有检查器**——一段永远报通过的比对代码比没有更危险。

三次实测（故意制造 / 消除漂移）：

| 改动 | 比对输出 | 退出码 |
|---|---|---|
| 把 `interactionAlpha` 从 0.01 放宽到 0.05 | `✗ hetero.f1 85.71% → 81.25%（-4.46pp）`、`✗ hetero.precision 92.31% → 76.47%（-15.84pp）` 等 25 处 | 1 |
| 把基线里 accuracy 改成 0.95 | `✗ accuracy 95.00% → 93.33%（-1.67pp）` | 1 |
| 无改动 | `✓ 全部一致（同 seed 下评测指标必须逐位相同，数据指纹也相同）` | 0 |

第二个用例顺带给了一个设计证据：**交互阈值放宽到 0.05，F1 掉 4.5pp、假阳性从 1 涨到 12**。0.01 这个默认值不是拍的。

## 5. 已知局限

1. **连续指标只接了 ARPU**（ARPU = Σ收入/Σ曝光）→ GMV 总量、留存率、人均时长等其它连续口径尚未接入；
   接入方式已经铺好（`metricType='continuous'` + 对应列），缺的是各自的业务口径定义与护栏。
2. **只有 7 天** → 新颖效应、长期效应无法分析。
3. **护栏只有退款率硬拦截** → 投诉率与延迟仅展示（低基数 / 非线性损失）。
   口径已升级：退款率走**非劣检验**（margin = 0.4pp，单侧 α = 0.005，非合并方差），
   延迟改走 **Bootstrap（BCa）** 而不是硬编码 sd 的假 t 检验。
   注意默认口径是「统计显著 ∧ 达到 margin」而非更严的「确认恶化超 margin」——
   因为后者需要观测差值 > margin + z₁₋α·SE ≈ 0.73pp，而本数据集注入的真实伤害只有 0.8pp，
   实测会漏掉约 38%（guardrail 族一致率跌到 46.7%）。这是样本量的约束，不是口径偷懒。
4. **合成数据 → 效应量两极分化**：注入的真实效应是 ±1.5~2pp、每臂约 2 万样本，检验力极高，
   于是贝叶斯 P(B>A) 基本只取两端（>0.95 或 <0.5）。这让全量 ECE 看起来很高（20.0%），
   但那是「精确 0 的真值被当作负类」造成的口径产物——只看真值非零的 70 个实验，ECE 是 **5.0%**（§3 表格上方有说明）。
   真实业务数据的效应量连续分布，ECE 会更接近两端之间，这个数字不能直接外推。
5. **分层 F1 的区间很宽**（0.667–0.970）：正例只有 15 个。想收窄只能扩数据集的异质实验数，
   不是调规则能做到的。
6. **主指标已换成稳健标准误，护栏仍是 i.i.d. 口径** → 同样存在过离散下偏乐观的问题；
   A/A 实测硬护栏误报 0.00%（名义 0.5%）尚在容忍内，但严格说应一并换成稳健口径（P2）。
   分层在连续口径下已走聚类方差（ratioTest），率口径下仍是两比例 SE——这是率口径分层
   在 A/A 上异质误判 0.4% 却仍偏低的原因之一，属已知残留。
7. **CUPED 需要前周期数据** → 导入的真实数据若没有 `preExposures/preConversions`，
   自动退回普通检验，界面上会明示当前用的是哪个口径。
8. **多重比较只做分层内 BH** → 未做跨维度 FWER 控制（P2，M12）。
9. **智能模式的 ablation 不进 CI** → 有随机性（temperature>0 时同文不同答，实测 ±2 条），
   只人工看并记录在 `docs/ABLATION-NOTES.md`。自动评测只覆盖规则模式——这一点不模糊化表述：
   CI 里的「幻觉数字率 0%」说的是**规则模式**，不是「DeepSeek 也不编数字」。
