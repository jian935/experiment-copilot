## 一、统计引擎深化 —— 简历最硬的部分（P1）

1. **贝叶斯层（Beta-Binomial）** ✅ 已完成（2026-11-01）
   - 现状：只有频率派，没有 P(B>A)、期望损失、可信区间。
   - 做：加 `bayesBetaBinomial(control, treatment)` → 输出 `P(B>A)`、95% 可信区间、期望损失（在 α 错的期望成本口径下）。
   - 价值：给出"这个实验有 98.3% 概率 treatment 更好"这种更直觉、且自带不确定性的表述；和频率派并排是面试亮点。
   - 落点：`src/lib/stats.ts` 新增 + `decide.ts` 结论卡加一行贝叶斯视角 + 单测对齐已知例子。
   - 实现要点：P(B>A) 用正态近似（两 Beta 后验差收敛到正态，与 95% 可信区间同源，规避大 n 下对 Beta CDF 陡台阶做数值积分漏分辨率的问题）；`betai`/`lgamma` 仍按闭式单测对齐。

2. **置信度 / 校准概率（填补蓝图最大缺口）** ✅ 已完成（2026-11-01）
   - 现状：决策是 4 类标签，**没有数值化的"把握"**。蓝图 M2/M5 反复要"置信度"，但 `Analysis` 里没有该字段，评测也没有校准曲线。
   - 做：基于 p 值 + 效应量 + 护栏距离 + SRM，输出一个校准后的"可上线把握"概率（或保持区间），再在评测看板出**校准曲线**（预测把握 vs 实际正确率）。
   - 落点：`decide.ts` 加 `confidence` 字段 → `EvalScreen.tsx` 加校准曲线面板 → `evaluate.ts` 加校准误差。
   - 实现要点：`confidence` 直接复用贝叶斯 `P(B>A)`（同一口径，避免两套"概率"打架）；`evaluate.ts` 出 10 桶校准曲线 + ECE，单测锁住"真实正效应实验平均置信度高于负效应"。

3. **序贯检验 / always-valid p（防 peeking）**
   - 现状：按固定 7 天快照判，没处理"每天看一次导致 α 膨胀"。
   - 做：加 alpha-spending（O'Brien–Fleming）或 mSPRT，给"如果中途每天看，需要多严的阈值"。蓝图 P2。
   - 落点：新 `src/lib/stats.ts` 函数 + 数据生成加"逐日 peek"维度。

4. **连续指标（ARPU/GMV）接入决策**
   - 现状：`welchTest` 已实现但注释明确"仅展示不参与决策"；真值只有二值转化率（`EVAL.md` 局限第 1 条）。
   - 做：合成数据加 ARPU（连续）、把 Welch 接入主指标/护栏的可选口径；评测加连续型实验真值。
   - 落点：`simulate.ts` 加 revenue 列 → `decide.ts` 支持 `metricType: 'continuous'` 分支。

5. **CUPED 方差缩减（演示用）**
   - 现状：完全没有。蓝图 P2。
   - 做：生成器加"实验前 7 天基线"协变量，演示 CUPED 把 CI 收窄 X%。纯展示也能讲故事。
   - 落点：`simulate.ts` 加 pre-period → `stats.ts` 加 `cupedVarianceReduction`。

6. **CI 覆盖率 Monte-Carlo 单测**
   - 现状：蓝图说要做"重复 1000 次、覆盖率≈95%"，目前只有静态单测。
   - 做：加一个非断言/断言松的覆盖率模拟测试，证明 Newcombe/Wilson 标称覆盖达标。

## 二、Agent 能力（P1 / P2）

7. **多轮追问上下文（填补单轮缺口）** —— P1
   - 现状：`answerQuestion(question, ctx)` **没有 history 参数**，模型看不到上一轮问答。
   - 做：把已发生的 `{q, reply, calls}` 回传模型，支持"那如果延一周呢？""刚才说的退款率具体是多少？"。
   - 落点：`answer.ts` 改签名 + `AgentPanel.tsx` 累积 messages。

8. **流式输出** —— P2（UI.md M7 已列）
   - 现状：一次性返回；工具调用过程已可见，但正文是整段。
   - 做：`fetch` + ReadableStream 接 DeepSeek streaming，按字吐出；审计徽章最后定稿。

9. **规划解释（Planner 可视化）**
   - 现状：工具有、调用可见，但没有"为什么选这些工具"的推理轨迹。
   - 做：加一个 `plan` 字段（工具调用前的思考），在 Trace 面板展示"先查 X 再查 Y"的链路。

10. **更多工具 + 模型无关**
    - 现状：9 工具固定，模型硬编码 `deepseek-flash`；`get_evidence`（单条证据深查）和序贯工具缺失（`bayesian_view` 已落地）。
    - 做：补 `get_evidence` / `sequential_check`；设置页可切 OpenAI 兼容模型。

11. **数字审计升级**
    - 现状：`audit.ts` 注释自己承认"符号不敏感"（`+2.1pp` 与 `下降 2.1pp` 都过）；只审计比例类，不审计概率/置信度数字。
    - 做：加符号校验（文案说"下降"但数字为正 → 标红）；把 p 值、概率也纳入白名单比对；审计结果接进 `evaluate.ts` 做"幻觉数字率"自动测。

## 三、评测体系补全（P1）

12. **幻觉数字率自动测（接进 evaluate）** —— P1
    - 现状：ablation 是手动跑的（`scripts/ablation.ts`），数字保真度没进 `evaluate.ts`；蓝图 10.2 的"幻觉数字率 ≤1%"没有自动口径。
    - 做：把 `audit.ts` 接到评测，对每题 Agent 回答算 suspicious 率，看板加一栏。

13. **分层检测 F1**
    - 现状：蓝图 10.2 有"分层检测 F1 ≥0.8"，实际评测没算（只算了异质识别 100%）。
    - 做：`evaluate.ts` 加 F1——对 heterogeneous 实验，模型/Agent 是否点名了"仅新用户有效"。

14. **按效应量 / 样本量分桶**
    - 现状：看板只有"按 p 值分桶"。
    - 做：加"按 |diff| 分桶""按样本量分桶"，说明准确率为何在小样本/小效应上塌。

15. **失败案例自动归因**
    - 现状：4 个 null 假阳性是人工写进 EVAL.md 的。
    - 做：自动归类为"小样本边界 / p 在 0.01–0.05 / 符号误判"，看板直接给归因饼图。
